# Auto Collector できること・仕様

版: **0.1.4.2**（2026-09-26 時点 / コミット 39bc8be）
対象: Dalamud プラグイン（DalamudApiLevel 15）

この資料は**ソースを読んで確認した内容**で書いてある。
未実装のもの、確認できなかったものは、そのように明記した。

---

## 1. このプラグインは何をするものか

ひとことで言うと **「通貨が貯まったら、自動で交換所へ行って交換する」**。

そこから派生して、次の機能を持つ。

| 機能 | 何をするか |
|---|---|
| **自動交換** | 通貨が閾値に届いたら、走っている自動処理を安全に止め、交換所へ移動して交換し、元の処理へ戻す |
| **FATE 自動周回** | FATE を探して移動・戦闘・離脱を繰り返す。バイカラージェムなどを稼ぐ |
| **収集品の納品** | 収集品を納品所へ持って行き、スクリップに換える |
| **製作して稼ぐ** | スクリップが足りないぶんを、収集品を作って納品して賄う |
| **リテイナーからの取り出し** | 製作の素材をリテイナーから引き出す |

---

## 2. 必要なもの・連携するもの

### 必須ではないが、機能ごとに要るもの

| プラグイン | 使いどころ | 無いとどうなるか |
|---|---|---|
| **vnavmesh** | 移動全般 | FATE 周回が使えない。交換所への自動移動も不可 |
| **BossMod Reborn** | FATE の戦闘 | FATE 周回が使えない |
| **Lifestream** | テレポート | マップ間の移動ができない |
| **AutoDuty** | 周回の中断・再開 | 連携しないだけ。交換自体は動く |
| **AutoRetainer** | リテイナー・ベンチャー | 取り出し機能が使えない |
| **Artisan** | 製作 | 製作して稼ぐ機能が使えない |

FATE 周回だけは **vnavmesh と BossMod Reborn の両方が必須**
（`FateRunner.IsUsable`）。片方でも欠けていると、稼ぎ方の一覧にも出ない。

## 4. 自動交換（中核機能）

### 4-1. 大前提：周回への相乗りとして動く

**プリセットを有効にしただけでは動かない。**
既定では **AutoDuty か Artisan が動いているときだけ**自動交換する
（設定「AutoDuty や Artisan が動作しているときだけ自動交換する」既定 ON）。

手で押す「行って交換」は、この設定に関わらず実行できる。

### 4-2. プリセットで設定できること

| 項目 | 既定 | 意味 |
|---|---|---|
| 名前 | 新しいプリセット | |
| 有効／無効 | 無効 | |
| **監視する通貨** | 数理（スロット 2） | トームストーンは**スロット番号**で保存するため、パッチで中身が入れ替わっても追従する |
| **交換リスト** | 空 | 複数の品を並べられる。上から順に交換 |
| 交換所 NPC | 自動選択 | 窓口を固定したいとき |
| **閾値** | 上限の 90% | 交換を始める条件（次項） |
| **どこまで交換するか** | 指定量の通貨を残すまで | （次々項） |
| 残す通貨量 | 500 | 「指定量の通貨を残すまで」のとき |
| 個数・回数 | 1 | 「指定回数だけ」などのとき |
| 製作して稼ぐ | OFF | 第 6 章 |
| 残す鞄の空き枠 | 10 | **製作用**。交換の関門ではない |

**交換リストの 1 行**には「交換する個数」と「所持数の上限」がある。
所持数の上限は**「持っていたら飛ばす」の二択ではない**。
上限 5 で 3 個持っていれば、足りない 2 個だけを交換する。

**交換対象の選び方**は、ゲーム内のアイテム交換画面と同じ
「系統 → 種別 → 品」の 3 段構成。名前での横断検索もある。
品は種別を開いたときに初めて読む（数千件を先読みすると固まるため）。

### 4-3. 閾値の 3 方式

| 方式 | 意味 | 発動条件 |
|---|---|---|
| 固定値 | その数に達したら | 所持数 ≧ 設定値 |
| **上限に対する割合**（推奨・既定） | 所持上限の N% に達したら | 所持数 ≧ 上限 × N/100 |
| 上限までの残り | 上限まであと N を切ったら | 所持数 ≧ 上限 − N |

**制約**: 割合と「上限までの残り」は、**所持上限が取れないと判定できない**。
取れない場合は交換しない（安全側に倒す）。

### 4-4. どこまで交換するか（4 種）

| モード | 動作 |
|---|---|
| **交換できる限り** | 通貨か所持枠が尽きるまで |
| **指定量の通貨を残すまで**（既定） | 設定した通貨量を割り込まない範囲で |
| **指定回数だけ** | 回数指定（1〜30） |
| **目標所持数に達するまで** | 報酬アイテムの所持数が目標に届くまで |

**重要な相互作用**

- 「目標所持数に達するまで」を選ぶと、**交換リストの行の「所持の上限」は見なくなる**。
  モードの目標が優先される
- **終わりを決める条件が 1 つも無いと交換しない。**
  「個数上限なし＋所持上限 0＋交換できる限り」の組み合わせは弾かれ、
  「個数・所持の上限・どこまで交換するか のいずれかを設定してください」と出る
  （ただし「製作して稼ぐ」を入れている場合は、素材が尽きるまでが正規なので通す）

### 4-5. 交換の実行と歯止め

| 歯止め | 値 | 理由 |
|---|---|---|
| 1 回の移動での交換回数 | **最大 30 回** | 交換は取り返しがつかないため、意図的に低く |
| 1 回の発火でまとめる個数 | 最大 20 個 | |
| **交換で残す鞄の空き枠** | **常に 2 枠**（固定） | AutoRetainer が空き 0 のキャラを対象外にするため |
| 交換 1 回ごとの間隔 | 1.2 秒 | 所持数の反映順序で誤判定しないため |

- **同じ窓口で扱える品だけをまとめて交換する。** 別窓口の品は次の判定で拾う
- 出発前に「行っても 1 回も交換できない」と分かる品は見送る
  （テレポートと周回の停止・再開を無駄に繰り返さないため）
- 交換の結果は**所持数の変化で検証**する。未確定のものは設定に記録され、
  **確定するまで新しい交換を受け付けない**（リロードやクラッシュを跨いで残る）

**自動無効化**: 同じプリセットで **2 回連続で失敗**すると、そのプリセットを
自動的に無効にして理由を残す。ただし**環境都合の失敗は数えない**
（中止・外部プラグインのエラー・鞄の空き不足・ショップが閉じた等）。

### 4-6. 対応している通貨

**アラガントームストーン** — `Tomestones` シートの全スロット。
ItemId ではなくスロット番号で保存するため、パッチで入れ替わっても追従する。
週上限のあるものは、今週の取得量と上限も追跡する。

**スクリップ** — クラフター／ギャザラーの紫貨・橙貨、詩学。
同梱の対応表とクライアントの実行時の値を**重ねて**使う。

実際に交換所の品のコストとして使われている通貨だけを一覧に出す
（白貨のような廃止済みは隠す）。
**選択中の通貨が一覧から消えても、黙って別の通貨に書き換えない。**

### 4-7. 交換候補の構築

ゲームデータから「この通貨で何がどこで買えるか」を作る。
ENpcBase が約 6 万行あるため、1 フレームあたりの処理量を抑えて少しずつ進める。

**利用者から見た制約**

- 通貨を選んだ直後は「交換候補を構築しています（進捗%）」になり、
  完成するまで交換は始まらない
- 索引は**1 通貨ぶんしか持てない**。別通貨のプリセットが並ぶと作りかけが捨てられる
- 手で押した交換は、完成を最大 60 秒待つ
- 構築に失敗すると 5 分のクールダウンが入る

## 5. 収集品の納品

手持ちの収集品をまとめて納品し、スクリップに換える。
**1 個ずつ撃って毎回確かめる**（まとめて撃つと何個成立したか分からなくなるため）。

### 自動で飛ばす・止める条件

| 条件 | 動作 |
|---|---|
| どのスクリップにも余裕がない | その場で終了 |
| 収集価値が納品の下限に届かない | その品を飛ばす |
| 納品するとスクリップが上限を超える | その品を飛ばす（全体は止めない） |
| 撃っても納品されなかった | 1 度だけ撃ち直し、駄目なら飛ばして続行 |
| **狙っていない収集品が減った** | **その場で停止**（取り違えの恐れ） |

品目ごとの報酬量はやってみるまで分からないため、**1 回目の納品で実測**し、
2 回目以降はその値で溢れるかを判断する。

### 行き先

「収集品納品窓口」をゲームデータから探す（NPC の番号は埋め込まない）。
扱うのは一般の納品窓口のほか、スカイスチール／リスプレンデント／モーエンの各ツール。

指定が無ければ**一般の納品窓口**から選び、いまいるエリア →
**アクセス済みエーテライトのあるエリア**の順で優先する。

### 納品と交換を交互に回す

```
収集品を納品 → スクリップが上限に近づいて停止
  → スクリップを使って交換 → 枠が空く
    → まだ収集品があれば納品へ戻る
```

止まらなくなるのを防ぐため、**納品する意味のある収集品だけを数える**。
「いま納品できる」と「交換すれば納品できる」を分けて扱う
（一緒にすると、納品へ行っては 1 個も納品できずに戻るループになる）。

一周して何も減っていない状態が 2 回続けば打ち切る。上限は 50 周。

**よくある詰まり**: そのスクリップを**減らす交換設定が無い**と、
そのスクリップを生む収集品は納品されない。その旨が画面に出る。

## 6. 製作して稼ぐ

プリセットに「製作して稼ぐ」を入れると、**欲しいアイテムが揃うまでを通しで回す**。

```
① 足りない素材をリテイナーから取り出す
② 鞄の空き枠まで収集品を作る
③ 納品する
④ スクリップが上限に達したら納品をやめる
⑤ スクリップを使って欲しいアイテムと交換する
   → まだ足りなければ ① へ戻る
```

### 判断の順番

1. 目標に届いた → 終わる
2. スクリップがもう足りている → 交換して終わらせる
3. 納品できる収集品を持っている → 納品と交換を回す
4. 素材が足りない → リテイナーから取り出す
5. 素材がある → 作る

順番には意味がある。2 を 3 より先に置かないと要らない収集品を作り続け、
3 を 5 より先に置かないと鞄が尽きる。

### Artisan との連携

**Artisan は必須**（無いと始められない）。

- **回数であって個数ではない。** 黒麦粉は 1 回で 3 個できるので、162 個なら 54 回
- **中間素材から先に作る**（素材切れで止まるため）
- 収集品は所持数を数えられないため、**鞄の枠を直接見て**終わりを判断する
- 「止める」を押したら耐久モードを直接落とす
  （停止要求の解除は Artisan 側が「再開」と解釈して残りを作り始めてしまう）

### 何を作るか

製作手帳の収集品欄と**同じ順**で候補を並べる（名前順・レベル順では手帳と見比べられない）。

1. **製作するジョブ**を選ぶ
2. レベル帯を選ぶ（帯が 2 つ以上あるときだけボタンが出る。50-60 / 61-70 / 71-80 / 81-90 / 91-100。**50-60 は Lv60 を含む**）
3. 収集品を選ぶ

橙貨はジョブごとに 1 件なのでジョブを決めれば自動で決まる。
紫貨はレベル帯ごとに複数あり、生むスクリップ量も違うので選ぶ必要がある。

**収集品を選ぶと設定が自動で変わる**

- 「製作して稼ぐ」が ON
- どこまで交換するかが「交換できる限り」
- 交換リストの全行の個数が 0（1 個ずつ窓口へ往復しないため）

製作の選択肢は「**製作で稼げる通貨**」のプリセットにだけ出る。
トームストーンのプリセットには出ない。

### 止まり方

| 条件 | 動作 |
|---|---|
| 何も動かない周が 2 回続く | 打ち切る |
| 素材が尽きた | **チャットへ通知**して停止（自分にだけ見える） |
| 呼び鈴が近くに無い | **30 秒後に自動で再試行** |
| 利用者が止めた | 利用者が操作するまで走り出さない |

暴走への歯止めは 5000 周。

## 7. リテイナーからの取り出し

製作の素材をリテイナーから引き出す。
Artisan の「Restock Inventory From Retainers」と同じことを自前で行う
（あちらは画面のボタンからしか呼べず、IPC が無いため）。

### AutoRetainer との関係

**AutoRetainer には何も依頼しない。やるのは競合の回避だけ。**

- `SetSuppressed` で**新規開始だけ**を止める。実行中の処理は中断しない
- **自分が立てた抑制だけを解除する**（他プラグインや利用者が立てたものは触らない）
- 未導入でも動く

**Allagan Tools には依存しない。** リテイナーを開けば持ち物は直接読める。

### リテイナーの持ち物を覚える

覚えていないと、1 種類の素材ごとに全員を開閉することになる
（実測で黒麦 1 種類のために 4 人で 14 秒）。

- **自分で開いたときだけでなく、人が手で開いたときも控える**
- **3 日より古い記録は当てにしない**。ただし**1 人ずつ**判定する
  （1 人だけ古いせいで全員ぶんが使えなくなるのを避ける）
- 「覚えたものを消す」操作もある

**行く前に在庫を見立てる**

| 判定 | 意味 |
|---|---|
| ある | 持っている人がいる。行く価値がある |
| 尽きた | **全員**の持ち物を覚えていて、どこにも無い。行かずに止める |
| 分からない | 覚えていない相手が 1 人でもいる。**行って確かめる** |

「知らないこと」を「無い」と決めつけない。

### 呼び鈴の場所を覚える

遠い呼び鈴はゲームのオブジェクト一覧に載らないため、場所が分からないと向かえない。

- 街だけでなく**宿屋や地下工房も同じ仕組み**で覚える
- **キャラクターでは分けない**（呼び鈴はワールドの設置物なので誰から見ても同じ）
- **当てが外れたら忘れる**（ハウジングの動かせる調度品を覚えても、1 度歩くだけで済む）

**制約**: 呼び鈴が近くに無いと素材を取り出せない。ただし 30 秒後に自動で再試行する。
納品窓口のそばには呼び鈴があるため、一度納品まで進めば以後は自力で回る。

## 8. AutoDuty との連携

### 周回の一時停止と再開

**Stop ではなく Pause を使う。** Stop は AutoDuty の内部処理を畳むため、
ダンジョン後に積まれたループ間処理（リテイナー・GC 納品・修理）の予約ごと消えてしまう。

**周回の維持**（設定 ON が既定）: AutoDuty が周回を終えて停止したら、こちらから再開させる。

- 手動停止と周回完了を区別する
- **再開したのに 20 秒以内に止まったのが 2 回続いたら諦める**
  （利用者が手で止めたのを押し返さないため）
- 渡せていない交換があるあいだは再開を待つが、上限 3 分

### AutoDuty 側の設定点検

画面に 8 項目のチェックリストが出る。多くは自動で直せる。

| 項目 | 期待値 | 理由 |
|---|---|---|
| 周回数 | **1** | 1 周ごとに交換の機会ができる |
| ループ間処理 | 有効 | 無効だと何も実行されない |
| **Run on last Loop** | **有効** | **ここが要。**無効だと 1 周設定で一度も実行されない |
| リテイナー連携 | 有効 | ダンジョン後にリテイナーへアクセス |
| リテイナーへ向かう猶予 | 0 より大（推奨 300） | 0 のままだとリテイナーへ行かない |
| GC 納品 | 有効 | 軍票交換と希少品の納品 |
| コンテンツから自動で出る | 有効 | 無効だとダンジョン内で停止し交換に入れない |
| 終了時の動作 | Do_Nothing（**自動で直さない**） | ログアウト設定だと毎周回それが走る |

### 版の制限

**AutoDuty 0.0.0.340 以上**が必要（設定で変更可、空にすると制限しない）。
古い版では設定の読み書きができず、ループ間処理の設定を確かめられないため、
この版を下回るあいだは**戦闘の自動周回を使わせない**。

## 9. FATE 自動周回

> **この章の記載の確かさ（2026-09-26 時点）**
>
> 指示書24（`docs/24_FATE周回_更新再検証と飛行進入の実装指示書.md`）への
> 対応をコードに入れた直後の状態。
>
> - **コードに入っている**：飛行進入の状態機械、納品の切り替え、
>   円外への退避、完了と未達成の区別、巡回ルートの固定、
>   プリセット検査の JSON 解析
> - **机上で検算済み**：外周点と降下の幾何（`tools/fate_geometry_check.py`）
> - **未実施**：ゲーム内での実走確認、黄金6エリアでの確認、
>   飛行軌跡の測定、納品成功の確認
>
> したがって以下の記述は「そう動くように書いた」であって
> 「そう動くことを確かめた」ではない。

### 9-1. 何をするか

1. 周回するマップの**一覧の上から順に**テレポートする
   （回る順は開始時に固定される）
2. そのマップで狙える FATE を選ぶ
3. マウントに乗って離陸し、**外周の上空**へ回り込む
4. そこから FATE の**中心の地上へ斜めに降りて**着地し、降車する
5. BossMod Reborn のプリセットで戦う
   （納品 FATE は 10 個たまったら納品へ切り替える）
6. 達成度 **100%** を見たら離脱し、**円の外へ出て**次の FATE へ
7. マップに狙える FATE が無くなったら、次のマップへ

### 9-2. 狙う FATE の選び方

次の条件を**すべて**満たすものだけが候補になる（`FateScanner.IsEligible`）。

| 条件 | 既定 | 設定名 |
|---|---|---|
| 進行中である（Running） | — | — |
| 達成度が上限以下 | **90%** 以下 | 残り時間・達成度 |
| 残り時間が下限以上 | **120 秒** 以上 | 同上 |
| 座標が取れている | — | — |
| 見送り中でない | — | （辿り着けなかった FATE は 5 分間見送る） |
| 納品 FATE を狙う設定か | 狙う | 納品 FATE も対象にする |
| レベル差が範囲内 | **無効** | レベルで絞る（既定オフ） |

候補が複数あるときの**優先順位**（`DefaultSortOrder`）は

1. **ボーナス付き**を優先
2. **達成度が高い**ものを優先（早く終わる）
3. **残り時間が短い**ものを優先（逃すともったいない）
4. **近い**ものを優先

### 9-3. パーティ同行

「パーティの仲間と同じ FATE を狙う」を入れると、**仲間が入っている FATE が
候補にあれば、そちらを優先**する。

- **同期はしない。** 仲間の座標を見て「どの FATE の円にいるか」を判定するだけ
- したがって**相手が同じプラグインを使っている必要は無い**
- 条件（残り時間・達成度・見送り中）は曲げない。仲間の FATE が条件から
  外れているなら、ふつうに選び直す
- 何人もいれば、いちばん多く集まっている FATE を採る

### 9-4. 移動と着地

> **記載の確かさ**
> 以下のうち「実装済」は 2026-09-26 の指示書24 対応でコードに入っているもの。
> **実機（ゲーム内）での確認は未実施**。数値は初期の試験値で、
> 実走して調整する前提のもの。

#### 飛んで入る段取り（実装済・実機未確認）

40m 以上離れた FATE へは、段階を分けて飛んで入る（`FateApproach.cs`）。

```
PlanEntry → Mounting → TakingOff → FlyToEntry
    → Descending → GroundConfirm → Dismounting → ReadyForCombat
```

| 段階 | すること | 次へ進む条件 |
|---|---|---|
| PlanEntry | 着地点と外周上空点を決める | 両方が決まった |
| Mounting | マウントに乗る（距離で断らない） | 騎乗した |
| TakingOff | 真上 5m への経路を渡してジャンプを促す | **飛行を 3 回続けて確認** |
| FlyToEntry | 外周上空点へ飛ぶ | 水平 5m 以内**かつ**高さ 8m 以内 |
| Descending | 中心の地上へ斜めに降りる | 水平 2m 以内かつ高さ +3m／−2m 以内 |
| GroundConfirm | 接地を確かめる | 位置が 5 回安定＋着地点の水平 10m 以内＋高さ +3m／−2m 以内 |
| Dismounting | 降車する | 騎乗が解けた |

**なぜ段階を分けるのか。** 以前は 1 つの関数で見ていたため、経路は
持ち上げた点へ頼み、到着は地上の点で測っていた。点が 2 つあるので、
「斜めに降りる」保証がどこにも無かった。段階ごとに目的地を固定し、
段階が変わったときだけ経路を引き直すことで、これを断った。

**経路は自分で求めてから渡す。** `Nav.PathfindCancelable` で求め、
中身を検査してから `Path.MoveTo` へ渡す。`SimpleMove.PathfindAndMoveCloseTo`
だと、探索が終わった瞬間に vnavmesh 自身が動き出すため、
引けた経路を見る隙が無い。

検査するもの：空でない・座標が有限・終点が目的地から 5m 以内・
**1 点だけの経路を（目的地が遠いときは）弾く**。
vnavmesh の `PathfindVolume` は結果の末尾に目的地をそのまま足すので
（`NavmeshQuery.cs:226-229`）、「末尾が目的地だった」は有効な経路の証明にならない。
つまり**この検査だけでは飛行経路をほとんど通してしまう**ため、
降下では次の形の検査を重ねる。

#### 斜めに降りていることを確かめる（実装済・検算済・実機未確認）

**vnavmesh は「指定の角度で降りる」API ではない。**
空間が開けていれば斜めの経路になりうるが、
「中央上空まで水平に飛んでから垂直に落ちる」形を返すこともある。
それを検査せずに走らせると、以前と同じ垂直落下になる。

経路の各点で「水平にどれだけ残っているか」と「高さがどれだけ残っているか」を測り、
**水平が尽きた（残り 3m 以内）時点で高さが 12m より多く残っていれば垂直落下**と見る。

垂直落下と分かったら、E から L を 4 分割（t=0.25/0.5/0.75/1.0）した
中継点を作り、**区間ごとに探索して検査してから連結する**。
補間した点へ直接向かわせはしない（その点が地形の内側かを誰も見ていない）。
それでも駄目なら進入の向きを変える。

`tools/fate_descent_check.py` で検算済み。

| 経路の形 | 判定 |
|---|---|
| 斜め（60,21.84 → 45,16.38 → 30,10.92 → 15,5.46 → 0,0） | 合格 |
| 中央上空まで水平 → 21.8m 垂直落下 | **不合格** |
| 中央上空まで水平 → 60m 垂直落下 | **不合格** |
| 末尾の落下 12m（上限ちょうど） | 合格 |
| 末尾の落下 13m | **不合格** |
| 最後 2.5m だけ落下（ふつうの着地） | 合格（誤検知しない） |

**上限は 3 分。** 段階ごとの上限だけだと、向きを変えてやり直すたびに
時間が積み上がり 20 分を超えうる。FATE は 15 分ほどで終わるので
間に合わない。切って地上の経路へ落ちるほうがまし。

#### 外周上空点と着地点の決め方（検算済）

- **着地点**：中心の真下の床。中心が湖や崖の上なら、中心から
  同心円状に 4 周 × 8 方向で探す。**1 度だけ求めて固定する**
  （動く敵を着地点にしない）
- **外周上空点**：中心から見て「いまいる側」の、半径 + 10m の位置。
  高さは「その場の床 + 8m」と「着地点から降下角 20 度で届く高さ」の大きい方
- 引けなければ向きを **0 / ±40 / ±90 度**と回して有限回試す。
  すべて駄目なら理由を付けて失敗させる

`tools/fate_geometry_check.py` で検算済み。半径 50m・余裕 10m・角度 20 度なら
外周点は水平 60m・高さ 21.838m、降下の途中（t=0.25/0.5/0.75/1.0）で
水平 60→45→30→15→0、高さ 21.84→16.38→10.92→5.46→0 と
**両方が単調に減る**。これは幾何の確認であって、ゲーム内で
その経路を通れることの確認ではない。

#### 飛べないとき（実装済・実機未確認）

- **飛べなかったことを、飛べたことにしない。** 離陸を 12 秒待って
  飛べなければ、理由（風脈未解放・クエスト未完了など）を付けて失敗させ、
  **地上の経路へ切り替える**
- 一度飛んで入れなかった FATE には、また飛ぼうとしない

#### 高度の上限（実装済・上限そのものは未確認）

上限はマップごとに違う。ログからの実測は
中央ラノシア 90 / 高地ラノシア 31 / 南ザナラーン 58。

飛んで届いた高さを覚えているが、**これは上限ではなく
「そこまでは行けた」という下限の証拠**でしかない。
初めて来たマップや、低く飛んだだけのマップでは記録が小さく、
それを上限として扱うと必要な高さに外周点を置けず、
指定の角度で降りられない。

そのため**記録より上を目指すことは禁じない**（余裕 25m を足して許す）。
本当に頭打ちなら、離陸（12 秒）や外周へ向かう段階（90 秒）の上限が
有限時間で拾い、向きを変えるか地上の経路へ落ちる。
**上限を読めていないので、保証はしない。**

### 9-5. 詰まったときの脱出

段階を踏んで抜ける。

1. **経路をなぞらせて引き直す**（追従の許容値を詰める）＋ジャンプ
2. **迂回**（進行方向に避ける球を置いて経路を引き直す。半径を広げながら 2 回）
3. **直接移動**（経路探索を通さず、立てる場所へ直接向かう。4 回まで）
4. **帰還**（それでも駄目なら、ホームポイントへ戻って脱出する）

どの段階でも抜けられなければ、その FATE は **5 分間見送って**次へ進む。

見張りは移動中・着地中・敵への接近中に働く。
**25 秒のあいだ 3m も動かなければ**、地形に挟まったとみなして脱出へ進む。

納品 FATE の報酬を待っているあいだは、足を止めてよいので見張らない。
ただし**次の FATE へ移動している最中は見張る**。
以前は報酬待ちが 1 件でもあれば段階を問わず見張りを止めていたため、
納品 FATE を 1 つ終えると約 1 分間、移動中の詰まりに気づけなかった。

### 9-6. 戦闘

戦闘は **BossMod Reborn に任せる**。専用のプリセット
`AutoCollector FATE` を自動で作り、有効にする。

- **BMR の AI（`/bmrai`）は使わない。** AI を入れるとプリセットが
  上書きされ、技もレベルシンクも動かなくなる
- 狙う・撃つ・寄る・シンクする、のすべてをプリセットの中で完結させる
#### 狙う相手は AutoCollector が決める（実装済・実機未確認）

**目指す挙動：自分からは FATE の敵にしか仕掛けない。ただし攻撃されたら反撃する。**

これは **BMR の設定だけでは表現できない**ことを確かめた。

- `AIHintsBuilder.cs:148` が**敵視のある敵を FateId に関係なく優先度 0** にする
- `AutoTarget.cs:224` が優先度 0 以上を候補に入れる
- **`Everything=Disabled` は「新しく引っ張らない」だけ**で、
  一度絡まれた FATE 外の敵は候補に残ったまま

そこで、狙う相手をこちら（`FateTargetService`）で決め、
BMR には「いま狙っている相手と戦う」ことだけをさせる。
一時方針で `Retarget=Never` を入れ、BMR に選び直させない
（`Never` は優先度の並べ替えまでは行い `ForcedTarget` を書く前に戻るので、
ジョブのモジュールは技を撃てる。`AutoTarget.cs:232-237`）。

| 判定 | 見るもの |
|---|---|
| **自分から仕掛ける相手** | `FateId` が自分の FATE と一致 **かつ** 円の中（+8m） |
| **反撃する相手** | ゲームの敵視リスト（`UIState.Hater`）に載っている |

- **`FateId` だけでは足りない**：隣の FATE の敵を拾う
- **円だけでも足りない**：通りかかった野良を拾う
- 敵視リストは BMR も同じものを読んでいる（`WorldStateGameSync.cs:258-265`）。
  RSR の「敵のターゲットが自分か」より確実で、敵が範囲攻撃の詠唱中に
  ターゲットを他人へ移す瞬間に取りこぼさない
- **一度見た敵視は 8 秒覚える。** 戦闘が切れると敵視リストは消えるので、
  その瞬間に「もう狙われていない」と判断すると生きた敵を残して離れてしまう
- 選ぶ順は「最大 HP が大きい → 近い」。強敵を倒さないと達成度が伸びない

- 敵が 15m より遠ければ、こちらから歩いて近づく

#### 納品 FATE：討伐と納品を切り替える（実装済・実機未確認）

```
討伐（0〜9 個）→ 10 個で納品へ → 成立したら討伐へ戻る
                                → 100% になったら離脱
```

- **納品そのものは BMR に任せる。** `FateUtils` が 10 個持っていれば
  納品 NPC を狙い、必要なら移動も強制する。主ターゲットは要らない。
  実際に「話しかける」のは `Plugin.cs:388` で、**`NormalMovement` が
  プリセットに入っていれば BMR の AI モードは不要**
- **納品中はこちらから敵への経路を積まない。** 積むと `FateUtils` の
  移動強制と引っ張り合いになる

**交戦中は納品できない。**
納品 NPC のダイアログは戦闘中に開かない（AutoFATEGrind の実測。
`AutoFate.Collect.cs:85`「whose dialog refuses to open in combat」）。
そのため段取りをこう組んだ。

1. 10 個たまったら `AutoTarget.General = Passive` を一時方針で入れ、
   **新しい敵を狙わせない**（`Passive` は Execute の冒頭で戻るだけなので
   技は撃てる＝絡まれたら反撃はできる。`AutoTarget.cs:110-111`）。
   狙っていた敵のターゲットも外す
2. **交戦中なら抑止を戻して振り払う。** 倒してからでないと納品できない
3. 戦闘が切れたら抑止を入れ直して納品へ
4. 成立・失敗のどちらでも抑止を戻す（戻さないと討伐へ帰っても敵を狙わない）

**プリセットは差し替えず、一時方針で部分上書きする。**
丸ごと差し替えると技のローテーションごと入れ替わり、戻すときに取りこぼす。
一時方針なら戦闘力はそのままで、狙う・動くだけを止められる。
AutoFATEGrind も同じ作法（`AutoFate.Collect.cs:159-161`）。
- **成立は「所持数が減った」ことで見る。** 進捗の上昇では判断しない
  （他人が納品したのかもしれない）。BMR が NPC を狙っただけでも
  成立にしない（狙っているだけで、渡せたとは限らない）
- **所持数が読めないときは 0 と扱わない。** 0 とすると「まだ集まっていない」と
  誤り、納品の途中で討伐へ戻って会話を中断する
- 30 秒進まなければやり直し、3 回で討伐へ戻る

**`CollectFATE` は Disabled にする。** BMR の `AutoTarget` は、この設定が
Enabled だと納品 FATE で `targetFateMobs` を**無条件に false** にする
（`AutoTarget.cs:167-168`。所持数は見ていない）。つまり 0 個の段階から
自分では敵を拾わなくなり、品が集まらない。

Disabled が正しい。`AutoTarget.cs:162` で `targetFateMobs = Progress < 100`
となり、171 行は `|=` なので false へ落とす力が無い。つまり討伐は止まらない。
10 個たまったあとの納品は、こちらの状態機械が面倒を見る。

### 9-7. その他の挙動

| 場面 | 動作 |
|---|---|
| 戦闘不能 | 既定は**レイズを待つ**。15 秒待って来なければ街へ戻る（設定で変更可） |
| バディ | 残り時間が 300 秒を切ったら呼び直す（既定 ON）。未所持なら呼ばない |
| 達成度 100% | **すぐにマウントに乗ってフライングで離れる**。地上を走らせない |
| 納品 FATE の報酬 | 100% でもすぐ報酬が入らないため、**最大 90 秒はマップを離れない**（待つ場所は円の外） |
| 達成できずに終わった | **完了には数えない**。「未達成」として別に数え、報酬待ちも積まない |

#### 円の外へ出る（実装済・実機未確認）

> **原則：達成度 100% になったら、すぐにマウントに乗ってフライングで離れる。**
> 地上を走らせない。

100% を見たら、次の候補があってもなくても、その場から飛んで離れる。

```
100% → 戦闘を切る（ターゲットを外す・オートアタックを止める）
     → 乗る（距離では断らない）
     → 真上 8m への経路で離陸
     → 飛んだら退避完了
```

**円の中の上空でも構わない。** 地上に居ないので敵に絡まれず、
次の FATE が決まればそのまま飛んで向かえる。
水平に離れておく意味が無いので、待たせない。

**乗るのは毎フレーム試す。** 待つのは、ゲームが受け付けないときだけ。

| 場面 | 乗れるのを待つ | 全体の上限 |
|---|---|---|
| 通常の FATE | **20 秒** | 30 秒 |
| 納品 FATE | 8 秒 | 15 秒 |

乗れない理由はたいてい一時的（戦闘が切れる直前、直前の操作の硬直、
降りた直後のリキャスト）で、少し待てば乗れる。
**待たずに歩き出すと、何もない場所へ走る動きになる。**

納品 FATE だけ短いのは、100% のあと報酬が入るまで最大 90 秒
マップに留まるため。ここで長く粘ると次の FATE を回る時間を削る。

**歩いて出るのは、飛べないエリア（風脈未解放）と、
待っても乗れなかったときだけ。**

**以前の不具合。** 退避先を「円の外の地上の点」（中心から 75m・
そのとき立っていた向きの延長線上）に決めて歩かせていた。
「円の外」という条件だけで選んだ点なので、そこには何も無い。
利用者からは「FATE が終わったあと、何もない所へ走って行く」
不審な動きに見えていた（2026-09-26 の報告）。
退避が済めば `Waiting` に戻るだけで、その 75m の移動には
「円から出る」以外の意味が無かった。

**まず戦闘を切る。** これが無いと飛んで離れられない。

- **ハードターゲットを外す。** 残っているとオートアタックが続き、
  **戦闘中はマウントに乗れない**ので飛べない
- BMR 側にターゲットを外す手立ては無い（`Plugin.SetTarget` は null を
  渡されると何もせず戻る。`Plugin.cs:432-437`）。**自分で外すしかない**
- 念のため、オートアタックが走っていればトグル（汎用アクション 1）で止める。
  トグルなので 500ms は間隔を空ける
- 退避の最中に絡まれて狙い直すことがあるため、退避中も毎フレーム見る

**以前の不具合。** `ReleaseCombat` はプリセットを外すだけで
ターゲットを外していなかった。さらに「プリセットを入れていなければ
何もしない」と早期に戻っていたため、入れる前に離脱すると
ターゲットが残ったままだった。これが「100% になっても
飛んで脱出しない」の原因。

- 成功の基準は**中心から「半径（最低 20m）+ 10m」以上**。この式は 1 箇所
  （`RetreatSuccessDistance`）にまとめてある
- **目標はさらに外に置く。** 経路は目標から 5m まで近づいた時点で
  切り上がるため、目標をちょうど基準に置くと届かない。
  基準 + 5m + 10m の位置を目標にする
- メッシュへ寄せた先が**円の内側なら、その補正を断る**。
  寄せる幅は最大 30m あり、円の外が崖や水の向こうだと
  「辿り着ける最近傍」が円の内側になる
- 戦闘が済んでいて 20m 以上あるなら**乗って出る**
- 引けなければ**向きを 90 度ずつ回して 3 回まで**試す。
  それでも出られなければ、出られなかったことを記録に残す
  （出られたことにはしない）

**以前の不具合。** 監視のときだけ FATE の中心を渡していたため、
「中心から半径 + 余裕の内側にいる」＝**円の中に立っている状態が「到着」**
になっていた。しかも詰まったときの引き直しが、円の中心へ向かう
経路になっていた。

### 9-8. ベンチャーの自動回収（実装済・検算済・実機未確認）

周回を始めるとベンチャーを見張り、回収できるようになったら街へ戻って回収し、
**元のマップへ戻って周回を続ける**。周回を止めると見張りも止まる。

```
周回を開始 → 見張り開始
  回収できるようになった
    → FATE の切れ目を待つ（戦闘中・納品中は抜けない）
      → 街へ移動（デジョン または テレポ）
        → 呼び鈴へ歩く → 開く → AutoRetainer が回収 → 閉じる
          → 離れたマップへ戻って周回を続ける
周回を停止 → 見張りも停止（回収の途中なら呼び鈴の画面も閉じる）
```

**回収そのものは AutoRetainer が行う。** こちらの役目は
「街へ行く」「呼び鈴を開く」「終わるのを待つ」「閉じる」だけ。

#### デジョンとテレポの使い分け

| 条件 | 行き方 |
|---|---|
| 行き先がホームタウンと**一致** | **デジョン**（無料） |
| 行き先がホームタウンと**不一致** | **テレポ**（料金がかかる） |
| すでにその街にいる | 移動しない |
| ホームタウンが読めない | **テレポ**（安全側） |

ホームタウンは `PlayerState.HomeAetheryteId` を読み、
`Aetheryte` シートでエリア番号に直して比べる。

**ホームタウンが読めないときはテレポに倒す。**
デジョンは行き先を選べないので、不明なまま撃つと意図しない街へ飛ぶ。

#### 行き先の設定

**既定はリムサ・ロミンサ。** ただし設定ファイルに固定値を最初から書かず、
エーテライトの一覧が読めた時点で当てはめる。リムサへアクセスしていない
キャラクターでは飛べない値になってしまうため。

選べるのは6都市（リムサ／グリダニア／ウルダハ／クリスタリウム／クガネ／
ソリューション・ナイン）のうち**アクセス済みのものだけ**。
ID を直接入れさせると、アクセスしていない街も選べて実行時に止まる。

画面ではホームタウンの行に「（ホームタウン・デジョン）」と出し、
選んだ街へどちらで行くかも表示する（料金がかかるかが分かる）。

#### 踏まないようにした罠

`C:\ソース\GbrVentureRelay`（採集で同じことをする自作プラグイン・実機確認済み）の
知見をそのまま当てはめた。

| 罠 | 対処 |
|---|---|
| **「分からない」を「無い」と読む** | 回収可否は Unknown / Collectable / None の3値。読めなかった一瞬で回収を落とさない |
| **自分で「残り0秒」と線を引く** | `AreAnyRetainersAvailableForCurrentChara` に聞く。本体は `UnsyncCompensation`（既定 -5秒）で判定しており、自分で引くとずれる |
| **一覧が空＝未アクセスと決めつける** | コンテンツ内では空になる。AutoCollector は一度これで止まっている |
| **呼び鈴が見えない＝無い** | 街に着いた直後は `Svc.Objects` が埋まっていない。45秒探し、一度見つけた場所は覚える |
| **フラグ1つで開閉を決める** | `OccupiedSummoningBell` はリテイナー一覧を開いている間に落ちる。画面の表示も合わせて見る |
| **止めずに画面を閉じる** | 閉じる前に AutoRetainer を止める。でないと相手が動いたまま画面だけ消える |

**切れ目まで待つが、待ちすぎない。** 戦闘中・納品中は抜けないが、
3分待っても切れなければそのまま向かう（敵が湧き続ける FATE では永久に切れない）。

**移動の入れ物は専用に持たせている。** 周回側と同じものを使うと、
呼び鈴への経路と FATE への経路が同じ入れ物を取り合う。

`tools/venture_travel_check.py` で検算済み（15件）。

| レベルで絞る | OFF | 入れると自分のレベル ±5 の FATE だけ狙う |

| バディを自動で呼ぶ | ON | |
| バディを呼び直す残り時間 | 300 秒 | |
| 戦闘不能のときの動作 | レイズを待つ | すぐ街へ戻る／ソロなら戻る、も選べる |

**コードから参照されていない**。購入は行われない。

## 11. 安全装置

### 11-1. 交換を始めてよいか

**不変条件：Duty 中は絶対に交換を始めない。**
AutoDuty を止めるのは Duty の外に出てから。

次の状況では交換を始めない。理由は 2 種類に分かれ、画面での見せ方も変わる。

| 状況 | 種類 |
|---|---|
| プレイヤーが利用できない／操作できない | 人の対応が要る |
| 戦闘不能 | 人の対応が要る |
| 画面の読み込み中 | 待てば解消 |
| **コンテンツに参加中** | 待てば解消 |
| 戦闘中 | 待てば解消 |
| エリア移動中 | 待てば解消 |
| カットシーン中 | 待てば解消 |
| 詠唱中／動作中／他の操作中 | 待てば解消 |
| トレード中 | 待てば解消 |

### 11-2. FATE 周回を続けてよいか

FATE 周回には**別の判定**を使う。
**戦闘中・詠唱中・動作中・戦闘不能は弾かない**（周回では正常な状態だから）。

弾くのは次だけ。

- プレイヤーが利用できない／画面の読み込み中
- **コンテンツに参加中**
- エリア移動中／**カットシーン中**／**トレード中**
- 操作できない状態

### 11-3. 緊急停止

`/autocollector stop` または各画面の「止める」で、次の順に止める。

1. 束ねている側（目標つき周回）から先に止める
   — でないと交換を止めた直後に製作や取り出しが始まる
2. 子の処理（リテイナー取り出し・製作）も直接止める
   — 製作計画タブから手で始めたものは、束ねている側からは止まらない
3. 交換を中止し、握った制御を解放する

FATE 周回も、周回中かどうかに関わらず止める。
止めたあと 20 秒は、あとから積まれた経路を捨て続ける
（経路探索は取り消せないため、完了した結果が勝手に積まれる）。

### 11-4. セルフチェック

起動時・ゲームバージョンの差分を検知したとき・交換開始直前に走る。
**1 つでも「失敗」があれば交換を開始しない。**

| 検査 | 落ちる条件 |
|---|---|
| ゲームバージョン | 変わっていたら**警告**（最初の交換は手動で確認を） |
| ゲームデータの改変 | 検出したら警告 |
| トームストーンの解決 | **1 件も解決できなければ失敗** |
| 週上限の整合 | 不整合なら警告 |
| 通貨の読み取り | **所持数が取れなければ失敗** |
| 連携プラグイン | 版が変わっていたら警告（IPC が変わっている可能性） |

## 14. 既知の制約

### 設定がキャラクター間で共有される

設定ファイルは **1 つだけ**（`DefaultConfig.json`）。複数のキャラクターで
同時に動かすと、後から保存したキャラの設定が他を上書きする。
**キャラクターごとに違う設定にはできない。**

### 周回マップの巡回順

**一覧の上から順**に回る。開始時は必ず先頭のマップへ向かうため、
別のマップで開始すると、まず先頭へテレポートする。

**回る順は、開始した時点で固定される。**
周回中にマップのチェックを変えても、その周回には反映されない
（次に開始したときから効く）。

これは以前の不具合を直したもの。生きた設定の添字を進めていたため、
A/B/C/D を並べて B を回っている最中に A のチェックを外すと、
一覧は B/C/D になるのに添字は 1 のまま。次に進めると 2 になり、
**C を飛ばして D へ飛んでいた**。

周回中に設定を変えたときは、画面に
「いま回っているのは…」「周回中の変更は、次に開始したときから効きます」
と出す。黙って効かないのでは分からない。

**開始前にテレポ先を確かめる。** 選んだマップのエーテライトが
1 つも引けなければ始めない。一部だけなら警告して、そのマップは飛ばす。

ただし**エーテライトの一覧が空のときは判断しない**。
一覧はコンテンツ（ID・レイド）の中では空になるため、
空を「1 つも解放していない」と読むと、解放済みのマップへ
「テレポ先が見つかりません」と言って開始を拒否してしまう。
この罠は一度踏んでいる（討伐中に「ソリューション・ナイン へ行けません」で
止まった。`AetheryteService.IsListReady` のコメントに実測が残っている）。

交換から戻ったときだけは、**離れたマップから再開**する
（巡回の順番ではなく中断の復帰なので）。

### 他プラグインへの影響

詰まったときに vnavmesh の経路追従の許容値を一時的に変える。
**これは vnavmesh 全体の設定**なので、変えている間は他のプラグインの
移動にも影響する。移動が終われば既定値へ戻す。
