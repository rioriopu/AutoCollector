## 1. 画面構成（上から順）

```
① いまの状態          常時・無条件（タブの先頭で必ず描く）
② 注意                該当時のみ・0 行なら何も描かない
③ 登録した交換        常時・プリセット単位
④ はじめに            既存 DrawSetupGuide をここへ移設（中身は変えない）
⑤ ▸ 連携プラグイン    折りたたみ・問題なければ畳む
⑥ ▸ 詳細（動作の確認用）  折りたたみ・既定で閉じる
```

現行の「アラガントームストーン 5 列表」「週制限つきトームストーンの今週の取得量」「所持枠の空き」「自動処理の状態」の 4 ブロックは、単独の表示としては廃止し、①②③⑥ へ吸収する。

### ① いまの状態 — `DrawHeadline()`

**`ImRaii.TabItem("状況")` の直後、`ListSlots()` の取得より前に無条件で呼ぶ。** これが `slots.Count == 0` のときに復旧手段が消える不具合の修正を兼ねる。

背景色つきの `ImRaii.Child` は使わない。高さを固定するとテキスト折り返しで欠け、`Vector2(0, 0)` は「残り領域全部」の意味になって画面を占有する。階層は色・改行・`Separator` だけで作る。

```
ImGui.Separator();
● 見出し                       ← レベル色。行頭の ● も同色
    補足（灰・TextWrapped）
    準備 › 移動 › 交換 › 復帰    ← 実行中のみ
    [ボタン] [ボタン]            ← 0〜2 個
ImGui.Separator();
```

レベル色: 赤 `DalamudRed`（人の操作が要る）／黄 `DalamudYellow`（処理中・もうすぐ）／灰 `DalamudGrey`（待機・未設定）／緑 `HealerGreen`（正常に監視できている）。

**状態は上から順に評価し、最初に当たった 1 つだけを描く。複数を並べない。**

判定に使う値は 2 種類に分ける。

- **ライブで読む**: `ExchangeExecutor.InFlight` / `.Step` / `.Failure` / `.StatusDetail`（実際の遷移でしか変わらないので毎フレーム読んでもちらつかない）
- **スナップショットから読む**: それ以外すべて（`MonitorService.Snapshot`。1 秒ごとに更新）

`SafetyGuard.IsSafeToStart` は `Player.IsAnimationLocked` / `IsOccupied` を見るため毎フレーム真偽が反転しうる（`SafetyGuard.cs:89-100`）。UI から直接呼ばず、必ずスナップショット経由にする。**表示の最短保持時間は入れない。** 1 秒スナップショットが保持時間そのものであり、さらに保持を重ねると失敗した瞬間に古い状態が数秒残るという逆の害が出る。

### ② 注意 — `DrawAttention()`

**「人がいま手を動かせば直るもの」だけ**を重大度順に並べる。件数の上限は設けない（上限を設けると、同時発生時にどれが落ちるかが実装ごとに変わる）。0 件なら見出しごと描かない。

### ③ 登録した交換 — `DrawPresetProgress()`

見出し `ImGui.TextUnformatted("登録した交換")` + `ImGui.Separator()`。

表は使わず、プリセット 1 件につき 3 行のブロックにする。並び順は `Plugin.C.Presets` の順（＝実際に選ばれる走査順）。

```
● 数理を硬化薬に        アラガントームストーン:数理 → 硬化薬
  [▓▓▓▓▓▓▓▓░░] 1,742 / 1,800    あと 58
  500 残るまで交換します
```

- 1 行目: `TextColored(dot, "●")` → `SameLine` → プリセット名 → `SameLine` → 灰で `{通貨名} → {報酬名}`
- 2 行目: `ImGui.ProgressBar(fraction, new Vector2(240f * ImGuiHelpers.GlobalScale, 0), $"{current:N0} / {trigger:N0}")` → `SameLine` → `あと {trigger - current:N0}`。`fraction = Math.Clamp(current / (float)trigger, 0f, 1f)`
- 3 行目: 灰で交換モードの言い換え（`ModeText`）

無効なプリセットは本体に並べず `ImRaii.TreeNode($"停止中のもの（{n}）##disabled")` に畳む。中で `DisabledReason` を赤で出し、`SmallButton("もう一度有効にする")`（`Enabled = true; DisabledReason = null; EzConfig.Save();`）を置く。`MonitorService.DisablePreset` は 2 回失敗で勝手に無効化する（`:204-208`）のに、現状は状況タブに復帰導線がない。

**UI で閾値判定を書き直さない。** ドットの色も「あと n」も `MonitorService.Snapshot` の値をそのまま描くだけにする。画面に「到達」と出ているものだけが実際に発火する、という一致をコードの構造で保証する。

### ④ はじめに — `DrawSetupGuide()`

**現行の `MainWindow.SetupGuide.cs` を 1 文字も変えずに、呼び出し位置だけを `DrawAutomationStatus` の中から③の直下へ移す。** 見出し文言、「あと {n} 件の設定が必要です」の畳み方、`DrawSetupItems` の 4 列（`""` / 設定 / 現在 · 推奨 / 場所と理由）はそのまま。

> AutoDuty を使わない構成です。周回に相乗りする場合は AutoDuty を導入してください。

### 2-4. `InFlight` の解釈 1 行

現行の `発火時 / 現在 / 差分` の 3 行（`MainWindow.cs:894-912`）を 1 行に置き換える。利用者に引き算をさせない。

```csharp
public static string DescribeInFlight(PurchaseAttempt a, CurrencyService currency)
{
    var currencyName = ItemName(a.CurrencyItemId);

    if (!currency.TryGetCount(a.CurrencyItemId, out var now) ||
        !currency.TryGetCount(a.RewardItemId, out var reward, includeEquipped: true, includeArmory: true))
    {
        return $"{a.RewardName} × {a.RewardQuantity} を交換しました。"
             + "いまの所持数を読み取れないため、ゲーム内で確かめてください。";
    }

    var dc = now - a.CurrencyBefore;
    var dr = reward - a.RewardBefore;

    if (dc == -(int)a.CurrencyCost && dr == (int)a.RewardQuantity)
    {
        return $"交換は成立しているように見えます（{currencyName} {a.CurrencyBefore:N0} → {now:N0}、"
             + $"{a.RewardName} {a.RewardBefore:N0} → {reward:N0}）。";
    }

    if (dc == 0 && dr == 0)
    {
        return $"交換されていないように見えます（{currencyName}・{a.RewardName} とも変わっていません）。";
    }

    return $"増減が想定と違います（{currencyName} {dc:+#;-#;0} / {a.RewardName} {dr:+#;-#;0}）。"
         + "ゲーム内で確かめてください。";
}
```

ボタン文言は現行の中立な **「確認したのでクリアする」** を維持する。「増えていました」にすると、増えていなかった人が押せるボタンを失う。

## 3. 通貨が 5 系統へ広がったときにどこが伸びるか

### そのまま使える部分
