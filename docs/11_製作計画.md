# 製作計画（リテイナーからの素材取得の準備）

## 決まる順番

```
欲しいスクリップ（橙 or 紫）
  → そのスクリップを生む収集品（レシピがあるものだけ）
    → 作る個数（鞄の空き枠から決まる）
      → 素材と個数（レシピ × 個数）
        → リテイナーから引き出す
```

**個数が決まらないと素材の数も決まらない。** 順番は飛ばせない。

## データの辿り方（実測で確認済み）

```
Item（収集品）
  └ CollectablesShopItem → CollectablesShopRewardScrip   何のスクリップをいくつ生むか
  └ Recipe.ItemResult                                    どのレシピで作るか
      ├ CraftType          ジョブ（調理・木工 など）
      ├ AmountResult       1 回で何個できるか
      └ Ingredient[] / AmountIngredient[]   素材と個数
```

実測（収集用のタコス・カルネ・アサーダ / ItemId 44232）:

```
IsCollectable=True  StackSize=1
Recipe 35829  ジョブ: 調理  作成数: 1
  ロネークの肩肉        ×2   StackSize=999
  黒麦粉               ×2   StackSize=999  ← 作れる（中間素材）
  ホワイトペッパー       ×1   StackSize=999
  ヤースラニガーリック    ×2   StackSize=999
  ファイアクリスタル     ×8   ← クリスタル
  ウォータークリスタル    ×8   ← クリスタル
```

橙貨を生む収集品でレシピがあるものは 87 件。

## 個数の決め方

**収集品は重ならない（StackSize = 1）。** 1 個作ると 1 枠使う。

素材も枠を使うため、作る個数と素材の枠は互いに影響する。
多い方から順に試して、収まる個数を採る。

```
作る個数 + 素材の新たに要る枠 ≤ 空き枠 − 残す枠
```

素材の枠は、いま持っているぶんで埋まっている枠との差で数える。

```
いまの枠   = ceil(所持 / 重なる数)
引き出し後 = ceil((所持 + 引き出す数) / 重なる数)
新たに要る枠 = その差
```

## クリスタルは数えない

クリスタルは鞄ではなく専用の入れ物に入る。
枠の計算にも引き出しにも含めない。

判別は `ItemUICategory` の名前が「クリスタル」かどうかで行う（18 件）。
番号は埋め込まない。

## 中間素材

黒麦粉のように、素材自体が作れるものがある。
足りない場合は先にそちらを作る必要がある。

いまは「作れる素材」と印を付けて知らせるだけ。
段数を辿って自動で作る仕組みは入れていない。

## いまの段階

**計算して出すだけ。リテイナーの中身には触らない。**

何をどれだけ引き出そうとしているのかを目で確かめてから、
引き出しの実装へ進む。

## リテイナーからの取り出し

Artisan の「Restock Inventory From Retainers」と同じことを自分で行う。
あちらは画面のボタンからしか呼べず、IPC も自動実行の設定も無い。

```
AutoRetainer を抑制
  → 呼び鈴に話しかける
    → リテイナーを選ぶ
      → アイテムの受け渡し（Addon 2378）
        → 目的の品を右クリック → すべて取る（Addon 98）／個数を指定して取る（Addon 773）
          → 閉じる → やめる（Addon 2383）→ 次のリテイナーへ
            → 一覧を閉じる → 抑制を解除
```

表記はすべて `Addon` シートから引く。文字列を埋め込まない。

### Allagan Tools は使わない

Artisan はどのリテイナーが何を持っているかを Allagan Tools から得ている。

こちらは使わない。リテイナーを開けば持ち物は
`InventoryType.RetainerPage1..7` から直接読める。
順に開いて、あるものを取り出し、足りたらやめればよい。
依存するプラグインを増やさずに済む。

### 取り出せたことの確認

**撃った回数ではなく、鞄の所持数が増えた数で数える。**
取り出せていないのに減らしてしまうと、足りないまま終わったことに気づけない。

増えなければ、その品はそのリテイナーでは諦めて次へ進む。
同じ品を探し続けて進まなくなるのを防ぐ。

### 抑制の解除

終わり方に関わらず必ず解除する。
握ったままにすると AutoRetainer が止まったままになる。
全体の制限時間（5 分）を超えた場合も同じ経路を通す。

### 前提

**呼び鈴の近くにいること。** 呼び鈴まで移動する処理は持たない。

## 収集品の選び方

### ジョブはプルダウン

`CraftType` から引く。自由入力では打ち間違いで出なくなる。

```
0 木工 / 1 鍛冶 / 2 甲冑 / 3 彫金 / 4 革細工 / 5 裁縫 / 6 錬金 / 7 調理
```

### レベル帯で絞る

紫貨の収集品は Lv50 から Lv90 まで広い。

```
Lv50 台 328 件 / Lv60 台 331 件 / Lv70 台 274 件 / Lv80 台 49 件 / Lv90 台 83 件
（全ジョブ合計）
```

そのまま並べると探せないため、Lv 帯のボタンで絞る。
レベルは `Recipe → RecipeLevelTable.ClassJobLevel` から引く。

**帯が 1 つしかない場合はボタンを出さない。**
橙貨は Lv100 だけなので、絞り込みは邪魔にしかならない。
「紫貨のときだけ出す」ではなく「帯が複数あるときだけ出す」という条件にしてある。
将来スクリップの階層が増えても同じ判断で動く。

### 並びは製作手帳と同じ

`RecipeNotebookList` から引く。

```
行 → その行に並ぶレシピ（順序つき）
並び順 = 行の番号 × 1000 + 行の中の位置
```

実測: 収集用のタコス・カルネ・アサーダ（Recipe 35829）は 手帳 Row 1463 の 5 番目。

名前順やもらえる量の順では、手帳と見比べたときに探せない。

## 収集品でないものが混ざっていた

`CollectablesShopItem` には、旧方式で納品できた**普通の品**も載っている。

木工 Lv50〜60 で引くと 42 件出たが、収集品は 6 件だけだった。

```
10614 バーチロングボウ            Lv58  IsCollectable=False   ← 混ざっていた
30970 収集用のシーダーロングボウ    Lv50  IsCollectable=True    ← 本来のもの
```

`Item.IsCollectable` で絞る。
これで製作手帳の収集品欄と件数が一致する。

## レベル帯は製作手帳と同じ区切り

**`50-60` は Lv60 を含む。** 10 で割った刻みではない。

```
91-100 / 81-90 / 71-80 / 61-70 / 50-60
```

実際の手帳（木工 50-60）に並ぶのは 6 件:

```
収集用のシーダーロングボウ            Lv50
収集用のシーダーフィッシングロッド      Lv52
収集用のホーリーシーダー・スピニングホイール Lv54
収集用のダークチェスナットロッド        Lv56
収集用のハロードチェスナットリング      Lv58
収集用のバーチシグナム                Lv60
```

帯が 1 つしかない場合はボタンを出さない。
橙貨は各ジョブ 1 件なので出ない。
「すべて」のボタンは置かない。手帳と同じく、常にどれかの帯を選んでいる形にする。

## 引き出せなかった原因（2026-09-13 実測）

利用者の実行記録から 2 つの誤りが確定した。

```
17:25:28.617  SelectEntrust: Neko-sam の持ち物を開いています
17:25:28.736  Withdraw: Neko-sam から取り出しています       ← 119 ミリ秒
17:25:33.139  取り出しの操作に失敗: 「個数を指定して取る」が見つかりません
17:25:44.915  終了: ロネークの肩肉 があと 117 / … 足りません
```

### 1. 「アイテムの受け渡し」を選べていなかった

`Addon` シートの文言に差し込み部分が含まれていた。

```
2378 「アイテムの受け渡し　[預託中：枠]」
```

実際の選択肢は「アイテムの受け渡し　[預託中：15枠]」のように数字が入る。
完全一致でも部分一致でも一致しない。

角括弧から後ろを落として照合するようにした。

参考:
```
  98 「リテイナーから受け取る」
 773 「リテイナーから受け取る（個数指定）」
2383 「リテイナーを帰す」
```
これらは差し込みが無く、そのまま使える。

### 2. 準備完了の判定が間違っていた

```csharp
var container = manager->GetInventoryContainer(InventoryType.RetainerPage1);
return container is not null && container->IsLoaded;
```

`RetainerPage1` は一度開くと読めるままになる。
「アイテムの受け渡し」を選ぶ前から読める状態のため、
選ばずに素通りしていた。記録の 119 ミリ秒がその証拠。

画面（`InventoryRetainer` / `InventoryRetainerLarge`）が
開いているかで判定するようにした。

**入れ物が読めることと、画面が開いていることは別物。**

## 作れる素材を逆引きする

リテイナーに完成品が無い素材がある。

```
17:32:44.924  終了: 黒麦粉 があと 162 足りません
```

黒麦粉は自分で作る素材で、リテイナーには置いていなかった。
この場合、その素材（黒麦）を取り出して自分で作ることになる。

```
黒麦粉: Recipe 5282  調理  1 回で 3 個
  黒麦 ×6
  ファイアクリスタル ×8   ← 除外
```

162 個要るなら 54 回、黒麦が 324 個いる。

### 計算

```
回数   = ceil(足りない数 / 1 回でできる数)
必要数 = 回数 × 1 回あたりの素材数
```

**1 段だけ辿る。** 何段も辿ると取り出す量が読めなくなり、
実際に必要になるのはたいてい 1 段。

### 取り出し方

先に完成品（黒麦粉）を探して全リテイナーを回る。
見つからなければ、その素材（黒麦）に切り替えてもう一度回る。

**先に完成品を探すのが大事。** 完成品があるのに素材を取り出すと、
作る手間が増えるうえ、鞄の枠も余計に使う。

切り替えは 1 回だけ。際限なく辿らない。

## 通し確認（2026-09-13 17:38）

```
17:38:26  ロネークの肩肉 を 166 個取り出します（このリテイナーに 249 個）
17:38:27  Withdraw: 取り出しを続けます            ← 反映を確認
…
17:38:38  黒麦粉 が 162 個足りません。素材を取りに行きます
17:38:38  取り出す対象を替えます: 黒麦×324
          → 全リテイナーを最初から回り直す
17:38:49  黒麦 を 324 個取り出します（このリテイナーに 675 個）
17:38:49  WaitWithdraw: 取り出しの反映を待っています
17:38:49  Withdraw: 取り出しを続けます            ← 114 ミリ秒で確認
17:38:52  終了: 必要なぶんをすべて取り出しました（324 個）
```

計算どおり（162 ÷ 3 = 54 回 × 6 = 324）。

**完成品を先に全リテイナー探してから素材へ切り替えている。**
黒麦粉を 7 人分探し、見つからなかったので黒麦に切り替え、
4 人目で 675 個のうち 324 個を取り出した。

## 自動製作

作るのは Artisan に任せる。こちらは「何を何回作らせるか」を決めて、
終わったことを所持数で確かめる役に徹する。

```
Artisan.CraftItem(ushort レシピ, int 回数)   作らせる
Artisan.IsBusy()                             終わったか
```

**回数であって個数ではない。** 黒麦粉は 1 回で 3 個できるため、162 個ほしいなら 54 回。

### 手順の組み立て

中間素材が足りなければ、それを先に作る手順を前に置く。

```
黒麦粉 ×54 回（162 個）
  → 収集用のタコス・カルネ・アサーダ ×83 回
```

黒麦粉が無いまま収集品を作らせても、素材が足りず止まるだけ。

### 終わりの判定

**所持数で見る。** Artisan が動いていないことだけでは、
始まる前なのか終わった後なのかを区別できない。

```
所持数が目標に届いた        → 次の手順へ
動きが止まったのに届かない  → 素材切れとして止める（3 秒待って確定させる）
```

### 始める前に弾く

中間素材でない素材が足りていない場合は、頼まずに理由を出して止める。
足りないまま始めても止まるだけで、何が起きたのか分かりにくい。

## 後回しにした改善

リテイナーを 1 種類ごとに総当たりしているため時間がかかる。

```
17:38:38 → 17:38:52  黒麦 1 種類のために 4 人分を開閉
```

開いたリテイナーの持ち物をその場で全部控えておけば、
2 周目以降は当たりのリテイナーへ直接行ける。

## リテイナーの持ち物を覚える（総当たりの解消）

1 種類の素材を取り出すたびに全員を開いて回っていた。
実測では黒麦 1 種類のために 4 人を開閉して 14 秒。

**リテイナーを開いた時点で、持ち物は `RetainerPage1..7` から全部読める。**
開いたついでに控えておけば、次からは当たりのリテイナーへ直接行ける。

### 覚える場面

- 取り出しで自分が開いたとき
- **人が手で開いたとき**

普段の出し入れで勝手に埋まっていく。特別な操作は要らない。

### 使い方

回る前に、欲しい素材を持っている人だけに絞り、持っている数の多い順に並べ替える。

```
持っている人だけを回ります: Nyanko-eleven(675) / K'erberos(120)
```

### 当てにできない場合は絞らない

- 1 人も覚えていない
- いちばん古い記録が 3 日より前

このときは**絞らずに全員を回る**。当てにならない記録で飛ばすと、
あるはずのものを取り逃す。

### 画面に出す

Allagan Tools に依存しないぶん、持ち物を把握できているかが分からなくなる。
製作計画に状態を出す。

```
リテイナーの持ち物: 8 人分を覚えています（最も古い記録 09/13 18:40）
```

覚えていない場合:

```
リテイナーの持ち物: リテイナーの持ち物をまだ覚えていません
  呼び鈴からリテイナーを開くと自動で覚えます。覚えるまでは全員を順に開いて探します
```

素材の表にも「リテイナー」の列を足し、誰が何個持っているかを出す。

| 素材 | … | 引き出す | リテイナー | 要る枠 |
|---|---|---|---|---|
| 黒麦 | | 324 | 675（1 人） | - |
| ホワイトペッパー | | 82 | 持っていません | 0 |
| ロネークの肩肉 | | 164 | 不明 | 1 |

行にマウスを乗せると、誰がいくつ持っているかと、いつ見たかが出る。

記録はキャラクターごとに分ける。別のキャラクターの記録は読まない。
