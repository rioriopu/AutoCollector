## 0. 先に：解析が不要と判明したもの

相談をまとめる過程で、**IDA を使わずに解決できる見込みが立ったもの**がある。
重複して調べてもらわないよう、先に書いておく。

### 「話しかけないと敵が出ない FATE」の判別 → **実機の構造体にあった**

`FateContext`（`FFXIVClientStructs/FFXIV/Client/Game/Fate/FateContext.cs`）に
そのものずばりの定義がある。

```csharp
[FieldOffset(0x10)] public uint MotivationNpc; // interact with this object to initiate fate
[FieldOffset(0x14)] public uint ObjectiveNpc;  // interact with this object to hand in items
```

- `MotivationNpc` … **話しかけて FATE を始める NPC**
- `ObjectiveNpc` … 納品を受け取る NPC

`Fate` シート（静的データ）には無かったが、実機のメモリにはあった。
**AutoCollector はこれをまだ使っていない**（未実装）。

→ これは自分で実装して確かめる。解析は不要。

## 1. いちばん困っていること：**実機で検証できていない実装が溜まっている**

これは解析ではなく開発の進め方の問題だが、いちばん重い。

いま `feat/bicolor-shop-map` ブランチに **133 コミット**ぶんの変更があり、
その多くが**机上検証（ゲームデータとの突き合わせ・ロジックの手計算）までしか
済んでいない**。実機で動かしたのはごく一部。

とくに未検証で、外すと困るもの：

| 実装 | 検証済みの範囲 | 未確認なこと |
|---|---|---|
| バイカラージェムの交換所 24 人・42 ショップ | ゲームデータと全件照合・誤り 0 件 | **実機で話しかけて品が並ぶか** |
| F.A.T.E達成度によるランク制限 | 交換サイトの表 96 件と一致 | 実機の表示・薄表示の挙動 |
| 納品 FATE の判定を直した（Rule 2/3 の取り違え） | 黄金 9 件が「見逃し→納品」に変わることを確認 | **実機で納品が最後まで通るか** |
| 飛行での FATE 接近 | 幾何計算・タイミングの机上計算 | 実機での挙動全般 |

→ ここは解析では解決しない。実機で回して潰していくしかない。

## 2. 解析してほしいこと → **全 5 件 回答済み（2026-09-27）**

| 項目 | 結果 |
|---|---|
| (1) `MaxRank` が 0 になる理由 | **解決**。`FateProgressUI` の `ReqFatesToRank2/3/4` で 0 でない列を数えれば上限ランクが出る。IDA 不要。**実装済み** |
| (2) SpecialShop | **データ側は確定**。他のショップは 635 件辿れるのにバイカラーだけ 0 件＝`npc_shop_links.json` は必要な補完。交換の確定は `AddonShopExchangeItemDialog.ExchangeButton`。状態は `ShopEventHandler` で読める。関数の呼び出し順は未着手 |
| (3) エリア・座標 | **解決**。LGB は開ける（パスに `bg/` を付ける）。1581/1712 件 |
| (4) `HandInCount` | **「FATE 単位の累計」が有力**（IDA 解析）。クライアントに加算もリセットも無く、`Progress` と同じ一括ゼロに含まれる。**確定は実機 1 回の観測** |
| (5) BMR の内訳 | **全容判明**。読んでいるのは 6 フィールドのみ。`ObjectiveNpc` をそのまま使い推論なし |

### 実装に直結する収穫

**`ShopEventHandler.VisibleItemsCount`** … 「実機で品が並ぶか」を目視せず判定できる。
§1 の未検証項目がひとつ自動確認に変わる。

```csharp
[FieldOffset(0x2A94)] public int VisibleItemsCount;      // 実際に並ぶ品の数
[FieldOffset(0x3261)] public bool WaitingForTransactionToFinish;
```

**`MapIcon` による NM 判定**（(5) の副産物）… `Rule=1` の 1156 件を
「通常討伐 624 / NM 討伐 436」に割れる。TSV の `大型`（`Unknown8`）は
**1712 件中 489 件で食い違うので NM 判定に使わない**。

**BMR との線引き**（提案をそのまま採用してよい）

| | BMR | AutoCollector |
|---|---|---|
| FATE 内の納品・収集 | ○ | — |
| どの FATE をやるか / マップ間移動 / 交換 / `MotivationNpc` | — | ○ |

### 残っている確認（実機 1 回で済む）

1. `HandInCount` … 10 個渡した直後に読む。0 に戻れば今回分、10 のままなら累計
2. `NeededFates` / `FateProgress` … 次ランクまでの必要数と現在の達成数（推定）
