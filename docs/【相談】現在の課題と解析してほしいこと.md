## 0. 先に：解析が不要と判明したもの

相談をまとめる過程で、**IDA を使わずに解決できる見込みが立ったもの**がある。
重複して調べてもらわないよう、先に書いておく。

### 「話しかけないと敵が出ない FATE」の判別 → **実機の構造体にあった**

`FateContext`（`FFXIVClientStructs/FFXIV/Client/Game/Fate/FateContext.cs`）に
そのものずばりの定義がある。

```csharp
[FieldOffset(0x10)] public uint MotivationNpc; // interact with this object to initiate fate
[FieldOffset(0x14)] public uint ObjectiveNpc;  // interact with this object to hand in items
```

- `MotivationNpc` … **話しかけて FATE を始める NPC**
- `ObjectiveNpc` … 納品を受け取る NPC

`Fate` シート（静的データ）には無かったが、実機のメモリにはあった。
**AutoCollector はこれをまだ使っていない**（未実装）。

→ これは自分で実装して確かめる。解析は不要。

## 2. 解析してほしいこと（優先度順）

### ★★★ 優先度 高

#### (1) F.A.T.E達成度の `MaxRank` が 0 になる理由

**症状**：`AgentFateProgress` の `FateProgressZone.MaxRank` が **0 のまま**。
`CurrentRank` は正しく読める（RANK4 が取れる）のに、上限だけ埋まらない。

そのため「全マップ最大か」を判定できず、
**全マップ COMPLETE なのに「0/6 マップ」と誤判定**していた。

```csharp
// FFXIVClientStructs/FFXIV/Client/UI/Agent/AgentFateProgress.cs
[StructLayout(LayoutKind.Explicit, Size = 0x150)]
public partial struct FateProgressZone {
    [FieldOffset(0x00)] public uint TerritoryTypeId;
    [FieldOffset(0x70)] public byte CurrentRank;   // ← 読める
    [FieldOffset(0x71)] public byte MaxRank;       // ← 0 のまま
    [FieldOffset(0x72)] public ushort FateProgress;
    [FieldOffset(0x74)] public ushort NeededFates;
    [FieldOffset(0x78)] public Utf8String RankText;
}
```

**確かめたこと**
- 構造体の定義は本家 FFXIVClientStructs と完全に一致（オフセットの誤りではない）
- `FateProgressUI` シートの列は**どのマップも 6**。実際の上限（漆黒3/暁月3/黄金4）と合わず、シートからは取れない
- 画面を開いたかは `AgentInterface.AddonId` で分かるはず（未実測）

**知りたいこと**
1. `MaxRank` はどの関数が書き込むのか。画面を開かないと埋まらないのか
2. 埋まらないなら、**上限を別の場所から取れないか**
   （`RankText` に「RANK 3/4」のような文字列が入っていれば、そこから読める）
3. `NeededFates` / `FateProgress` の意味（次のランクまでの必要数？）

**いまの回避策**：`MaxRank` が読めないときは
「その拡張で到達している最高ランク」を上限とみなしている。
全マップ同ランクで未到達のときだけ誤る（都市へ行って空振りする）。

#### (2) 交換画面（SpecialShop）を確実に開く／操作する手順

**症状**：交換の実行そのものは動いているが、**経路が複数あって条件分岐が読み切れていない**。
NPC によって「話しかけたら即ショップ」「会話メニューを選ぶ」
「InclusionShop（アイテム交換）経由」と違い、実測で継ぎ足してきた。

とくにバイカラージェムの交易商 24 人は、**シートからは NPC へ辿れない**
（`ENpcData` 直接 0 件 / PreHandler 0 件 / TopicSelect 0 件 / InclusionShopSeries 0 件）。
外部データ（`npc_shop_links.json`）で補っているが、実機で全員確かめていない。

**知りたいこと**
1. NPC に話しかけてから SpecialShop が開くまでの関数の流れ
2. `EventHandler` の種類（0x000B = CustomTalk 等）ごとの分岐条件
3. **どの Addon のどのコールバックが「品を選んで交換する」の本体か**
   （いまは `AtkUnitBase` のコールバックを実測で当てている）

### ★★ 優先度 中

#### (3) FATE の「エリア・座標」を静的データから引く方法 → **解決済み（2026-09-27）**

**解決した。IDA は不要だった。** 原因は私のパスの組み立てミス。

```csharp
var dir = bg[..bg.LastIndexOf('/')];   // 末尾セグメントを落とす（ここは合っていた）
var path = $"bg/{dir}/planevent.lgb";  // ★ 先頭の "bg/" を付け忘れていた
if (!gd.FileExists(path)) return;      // GetFile は見つからないと null を返す
```

`GetFile<T>()` は例外ではなく `null` を返すため、そのまま `.Layers` に触って
`NullReferenceException` になり、「Lumina が LGB を開けない」ように見えていた。

手元で再現して確認：**LGB 1788 ファイル / インスタンス 2,241,913 件**を索引化し、
`Fate.Location`（EventRange の InstanceId）から **1581 / 1712 件**を解決。

成果物は `C:\ソース\FF14_FATE一覧\FATE一覧_全件_座標付き.tsv`（25 列）。
ワールド座標に加え、ゲーム画面と同じマップ座標も入っている。

#### (4) 納品 FATE の「集めた品の個数」を確実に数える方法

**症状**：いまは `InventoryManager.GetInventoryItemCount` で
`EventItem` の ID を数えているが、**読めないことがある**（`null` を返す経路がある）。

納品 FATE は「10 個集めて NPC へ渡す」を繰り返すため、
個数を読み違えると、途中で討伐に戻ったり、渡しそびれたりする。

**知りたいこと**
- `FateContext.HandInCount`（`0x3AE`）が「今回渡した数」なのか「累計」なのか
- 所持数を数えるのに、`EventItem` を直接数える以外の正しい方法があるか
