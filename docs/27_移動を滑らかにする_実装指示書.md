## 1. 何を直したいのか

いまのキャラクターの動きは **直線 — 直角 — 直線** になる。
曲がり角で一度ほぼ止まり、向きを変えてまた走り出すため、見るからに機械的。

これを **直線 — 湾曲 — 直線** にしたい。曲がり角を弧で丸め、
速度を落とさずに回り込む、人がやる動きに近づける。

### なぜそうなるのか

vnavmesh の経路は、ナビメッシュのポリゴンの境目を結んだ**折れ線**で返る。
追従する `FollowPath` は「次の点へ向かって直進する」だけなので、
折れ線の角がそのまま動きの角になる。

公式はここを滑らかにしない。**つまりこれは公式に足りない差分であり、
こちらで補ってよい領域**にあたる。経路探索そのものには一切手を入れない。

## 3. 先に試すべき安い手（比較の基準にする）

本題の前に、**1 行で済む手**がある。必ずこれを先に測ること。

```csharp
navigation.SetTolerance(0.8f);   // 既定は 0.25
```

`Tolerance` は「経路からどれだけ外れてよいか」。大きくすると vnavmesh 自身が
曲がり角を内側に端折るので、**ある程度は勝手に丸くなる**。

ただし欠点がある。

- 丸める場所を選べない。狭い通路でも端折るので、壁に擦る
- 外れてよい量が増えるだけで、弧を描くわけではない。角は残る

**やること:** `0.25 / 0.5 / 0.8 / 1.2` の 4 段で見た目を比べ、記録に残す。
これが本実装の比較対象になる。ここで十分なら本実装は要らない。

## 4. 本実装の設計

### 4.1 置き場所

新しいクラス **`AutoCollector/Automation/PathSmoother.cs`** を作る。
`NavigationService` から使う。**設定で切り替えられるようにし、既定は無効**にする
（`Config.cs` に `bool SmoothPath` を足し、設定タブに出す）。

実機で比べられないと良し悪しが決まらないため、切り替えは必須。

### 4.2 流れ

```
① 経路を求める      Nav.PathfindCancelable(from, to, fly) → List<Vector3>
② 間引く            ほぼ一直線に並ぶ点を落とす（Ramer–Douglas–Peucker）
③ 角を丸める        各頂点を二次ベジェの弧に置き換える
④ 検査する          生成した点がすべてメッシュに乗っているか
⑤ 渡す              Path.MoveTo(points, fly)
```

②が要る理由: ナビメッシュの経路はポリゴンの境目ごとに点が入るため、
**直線の途中にも点が並ぶ**。そのまま角を丸めると、角でない場所まで
丸めてしまい、経路全体がうねる。

④が要る理由: **角を丸めるとは、内側へ切り込むこと**。切り込んだ先が
壁の中かもしれない。確認せずに渡すと壁へ突っ込む。ここを省いてはいけない。

### 4.3 ② 間引き（Ramer–Douglas–Peucker）

```
入力: List<Vector3> path, float epsilon = 0.3f
出力: 端点を保ったまま、元の折れ線から epsilon 以上離れない部分列
```

- 距離は **XZ 平面で測る**（高さを混ぜると坂で誤って落ちる）
- `epsilon` は 0.3 ヤルム程度から。大きくすると経路が元から離れる
- 先頭と末尾は必ず残す

### 4.4 ③ 角を丸める

間引いた点列 `P[0..n-1]` の、**内側の頂点** `P[i]`（0 < i < n-1）ごとに:

```
a = P[i-1], b = P[i], c = P[i+1]

turn = b から a への向きと、b から c への向きのなす角
```

- `turn` が **160 度以上**（ほぼ直進）なら、丸めずに `b` をそのまま使う
- それ以外は、`b` を弧で置き換える

弧の作り方（二次ベジェ）:

```
r = min(MaxRadius, |a-b| * 0.45, |b-c| * 0.45)

in  = b + normalize(a - b) * r      // 弧の入口
out = b + normalize(c - b) * r      // 弧の出口

弧上の点 = Bezier(in, b, out, t),  t = 1/(k+1) .. k/(k+1)
Bezier(p0, p1, p2, t) = (1-t)^2 * p0 + 2(1-t)t * p1 + t^2 * p2
```

- `MaxRadius = 2.5f`（既定）。大きいほど大回りになる
- `* 0.45` は、隣り合う弧が重ならないようにするため（半分より少し内側）
- `k = 3`（弧を 3 点で表す）。増やすと滑らかだが点が増える
- **Y は線形に補間する。** 高さを曲げる意味はないうえ、坂で浮く

結果の点列は `[P[0], in, 弧上の点…, out, (次の頂点の in), …, P[n-1]]`。

### 4.5 ④ 検査

生成した**すべての点**について:

```csharp
vnavmesh.TryIsPointOnMesh(point, halfExtentY: 2f, allowUnreachable: false, out var onMesh)
```

- `onMesh` が false の点が **1 つでもある弧は、まるごと捨てる**。
  その頂点は元の `b`（角のまま）に戻す。弧ごとに判定し、経路全体は捨てない
- `TryIsPointOnMesh` が false を返した（＝IPC が答えられなかった）場合も
  捨てる側に倒す。**読めないことを「乗っている」と読まない**

さらに、**出来上がった点列の隣り合う 2 点が 0.1 ヤルム未満なら片方を落とす**。
点が詰まりすぎると追従が震える。

### 4.6 ⑤ 渡す

```csharp
vnavmesh.TryMoveAlong(points, fly);
```

渡したら、`NavigationService` のいまの仕組み（到着判定・詰まり検知・
引き直し間隔）はそのまま使える。**そこには手を入れない。**

ただし 1 つだけ注意: 引き直しのとき、`NavigationService` は
`TryMoveCloseTo` を呼んでいる。滑らか版を使っている間は、
引き直しも滑らか版を通さないと、引き直した瞬間だけ角張る。
`NavigationService` 側に「いま滑らか版で動かしている」ことを持たせ、
引き直しも同じ経路で行うこと。

## 6. やってはいけないこと

- **経路探索を自前で書かない。** 必ず vnavmesh に求めさせる
- **検査（4.5）を省かない。** これを省くと壁に突っ込む。必ず入れる
- **飛行中の経路を丸めない。** 空中は `FateApproach` が段階を組んで降ろしている。
  そこへ別の滑らか化を混ぜると、降下の形の検査（`IsDescentAcceptable`）が壊れる。
  **`fly == true` のときは素通しにする**
- 既定を `true` にしない。実機で比べてもらうまでは無効のまま

## 7. 受け入れの基準

1. `SmoothPath = false` のとき、**動きがいまと一切変わらない**こと（経路に触れない）
2. `SmoothPath = true` で、曲がり角で止まらずに回り込むこと
3. 狭い通路・階段・橋で、壁に引っかかる回数が増えていないこと
4. 弧が捨てられた（4.5 で false になった）回数がログに出ること。
   `AnomalyLog` の `Info` で「丸めを諦めた角: n 箇所」程度
5. ビルドが 0 エラーで通ること
