# 4 本のブランチを 1 本へ収束させた

作業ブランチ: `integration/all`（版 0.1.4.0）

## なぜまとめたか

検証待ちのブランチが 4 本たまり、利用者は**一度に 1 つの DLL しか動かせない。**
1 本ずつ確認していると、確認が終わるまで次が進まない。

```
fix/accessory-index-range   0.1.2.9  アクセサリの交換
feature/multi-cost-exchange 0.1.3.0  武器の対価 2 つ（アクセサリを内包）
feature/earner-modules      0.1.3.6  稼ぎ方のモジュール化 段 0-5
feature/estell-ui           0.1.3.7  画面を EstellUtils へ
```

`feature/estell-ui` だけは **0.1.3.5 で実機を通っている。**
それを土台に、残りを重ねた。

## まとめた順

```
main
 └ feature/estell-ui        実機確認済みのものを先に置く
    └ feature/multi-cost-exchange  （アクセサリ修正を内包）
       └ feature/earner-modules
```

### 手で直した衝突は 2 か所だけ

| 場所 | 中身 | どうしたか |
|---|---|---|
| `AutoCollector.csproj` | 版番号が 3 つ | まとめた版として **0.1.4.0** |
| `Plugin.cs` | `using` の並び | 両方残した |

ほかは自動で解けた。触っている場所が分かれていたため。

## マージで消えていないことの確認

**ビルドが通るだけでは足りない。**
自動マージは、片方の変更を黙って落とすことがある。
各ブランチの要点が残っているかを 16 項目で確かめた。

| 由来 | 確かめたこと |
|---|---|
| アクセサリ | `TryGetShopItemCount` / index の上限がショップ側 / 区分の切替 / 3 種の失敗を設定の誤りに数えない |
| 武器の対価 | `ExtraCosts` / `CanExecute` 一本化 / 歯止めが素材も見る / 払ったぶんの減りを検証 |
| モジュール化 | `Earning/` 一式 / Executor から AutoDuty と Artisan が消えた / `ExternalAutomationGate` を畳んだ / 戦闘プリセットの製作指示を止めた |
| EstellUtils | `EuWindow` / 主画面と設定の両方へ / `EzConfigGui` を外した / `RawImGui` で囲む |

結線も確認した（`ExchangeExecutor` の引数が稼ぎ手に差し替わっていること、
`Plugin` が `Combat` / `Crafter` / `Earners` を渡していること、
`EvaluateAllowance` が `ReadExtraCosts` を渡していること）。

## main へ入れる条件

**まだ入れない。**`main` には実機で確認が取れたものだけを置く。

この 1 本で次を見てもらい、通ったら `main` へマージしてタグを打つ。

| # | 見るもの | 確かめ方 |
|---|---|---|
| 1 | アクセサリの交換 | ジルコンで ItemId 46535 を交換。**通貨が 375 減って所持が 1 増える** |
| 2 | 武器の対価 2 つ | 対価が 2 つある品を選ぶ。素材の必要数と所持数が出る。**通貨と素材の両方が減る** |
| 3 | 中断と復帰 | 周回が止まり、交換して、また周回に戻る |
| 4 | 段の表示 | 状況タブが「自動処理をいったん止めています」「自動処理を再開しています」 |
| 5 | 戦闘プリセット | トームストーンの設定に**製作の指示が出ない** |
| 6 | 画面 | 0.1.3.5 と見た目・操作が変わっていない |

**1 つでも駄目なら main は動かさない。**作業ブランチで直して押し直す。
