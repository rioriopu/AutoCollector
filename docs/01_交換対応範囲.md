# Auto Collector — 交換対応範囲 仕様書

作成日: 2026-08-25
状態: レビュー待ち（未確定事項あり → 末尾「要決定事項」参照）

本書は、引き継ぎ済みの 2 つの仕様書（`FFXIV トークン自動交換・周回連携プラグイン 開発仕様書.md` / `Token Exchange Automation Plugin.md`）を踏まえ、
**実際のゲームデータ（Lumina 経由で解析済み）** に基づいて「どの交換に、どこまで対応するか」を確定させるための資料である。

記載している ID・件数・シート名はすべて現行クライアントのデータから実測した値であり、推測値は含まない。

---

## 1. 大前提：FFXIV の「交換」は 5 系統に分かれる

仕様書では「通貨 → アイテム」を一様に扱っているが、実際のゲームデータ上は
**シートも UI（Addon）も別物の 5 系統**に分かれる。実装コストと破損リスクが系統ごとに違うため、まずここを分離する。

| 系統 | 参照シート | 交換 UI | コスト表現 | 代表例 |
|---|---|---|---|---|
| **A. 汎用 SpecialShop**（アイテムコスト） | `SpecialShop` | `ShopExchangeCurrency` / `ShopExchangeItem` | `ItemCost` に ItemId 直値（≧8） | バイカラージェム、トロフィークリスタル、セントリオ記章、モブハントの戦利品、蒼天街振興券 |
| **B. トームストーン** | `SpecialShop`(`UseCurrencyType=4`) + `Tomestones` / `TomestonesItem` | `ShopExchangeCurrency` | `ItemCost` が **`Tomestones` シートの行番号**（1〜4） | 数理・記憶・詩学 |
| **C. スクリップ** | `SpecialShop`(`UseCurrencyType=16`) / `InclusionShop` | `ShopExchangeCurrency` / `InclusionShop` | `ItemCost` が **クライアント内部の特殊通貨インデックス**（1,2,4,6,7） | クラフター／ギャザラー 紫貨・橙貨 |
| **D. 軍票（グランドカンパニー）** | `GCScripShopItem` / `GCScripShopCategory` / `GrandCompanyRank` | `GrandCompanyExchange` | `CostGCSeals`（uint 直値） | 黒渦団／双蛇党／不滅隊 軍票 |
| **E. 収集品納品** | `CollectablesShopItem` / `CollectablesShopRefine` / `CollectablesShopRewardScrip` | `CollectablesShop` | ―（通貨を**得る**側） | 収集品 → 紫貨／橙貨 |

**重要**：本プラグインの「交換」は A〜D、「納品」は E。E は通貨を消費せず取得する側なので、状態機械も別扱いにする。

## 2. 対応 Tier（実装優先度）

### Tier 1 — MVP 必須：アラガントームストーン（系統 B）

`Tomestones` シートは**スロット定義**であり、行番号が固定で中身がパッチごとに入れ替わる。実測値：

| Tomestones 行 | 現在の割当 | ItemId | 所持上限 | 週上限 |
|---|---|---|---|---|
| 1 | アラガントームストーン:詩学 | 28 | 2,000 | なし |
| 2 | **アラガントームストーン:数理** | 48 | 2,000 | なし |
| 3 | **アラガントームストーン:記憶** | 49 | 2,000 | **450** |
| 4 | アラガントームストーン:天道 | 47 | 2,000 | なし |

- 本プラグインは **ItemId 48 を直接ハードコードしない**。`Tomestones` 行 2／3 を参照して現行トームストーンを自動解決する。
  これによりパッチで数理→次の通貨に入れ替わっても設定を書き換えずに追従できる（文書B §50 の要求を構造的に満たす）。
- 週上限（`Tomestones.WeeklyLimit`）も取得できるため、UI に「1,742 / 2,000（週 320/450）」の形で表示できる。
- 交換ショップ数：`UseCurrencyType=4` の SpecialShop は **249 ショップ**。
- **ファントムウェポン関連の石も、この系統の通常 SpecialShop エントリとして扱う**（専用ハードコード不要）。

### Tier 2 — 軍票（系統 D）

- 交換品エントリ総数：**857 件**（GC 3 種 × Tier 3 段 × サブカテゴリ 4 種 = 36 カテゴリ）
- 階級別の軍票上限は `GrandCompanyRank.MaxSeals` から取得（固定値 90,000 等をハードコードしない）：

  | 階級 Tier | MaxSeals |
  |---|---|
  | 1（三等兵〜） | 10,000 → 25,000 |
  | 2 | 30,000 → 45,000 |
  | 3 | 50,000 / 80,000 / 90,000 |
  | 4 | 100,000 |
  | 5 | 150,000 |
  | 6 | **200,000** |

- 各交換品に `RequiredGrandCompanyRank` があるため、**階級未達は交換前に判定してスキップ**できる（文書B §24 の要求を満たす）。
- 仕様書に名指しされた交換品を実データで確認済み：

  | 仕様書の記載 | 実在するか | 正式名称 / ItemId |
  |---|---|---|
  | ベンチャースクリップ | ○ | ベンチャースクリップ / **21072** |
  | 絶霊布 | ○ | 絶霊布 / **10120** |
  | グランドカンパニー・テレポ券 | △ 名称不一致 | **転送網利用券:黒渦団 21069 / 双蛇党 21070 / 不滅隊 21071** |

  ※ 仕様書の「グランドカンパニー・テレポ券」という名称のアイテムは存在しない。実体は上記「転送網利用券」（GC 別 3 種）と判断した。認識が違う場合は指摘してほしい。

- 通貨 ItemId：黒渦団軍票 **20** / 双蛇党軍票 **21** / 不滅隊軍票 **22**（いずれも Stack 200,000）

### Tier 3 — ギャザラー／クラフタースクリップ（系統 C）＋ 収集品納品ループ（系統 E）

現行スクリップの ItemId（実測）：

| 通貨 | ItemId | 所持上限 |
|---|---|---|
| クラフタースクリップ:紫貨 | 33913 | 4,000 |

### Tier 4 — 汎用 SpecialShop（系統 A）

トームストーン／軍票／スクリップ以外の交換型通貨。実測で **コストとして使われているアイテムは数百種**存在する。主なもの：

| 通貨 | ItemId | 交換先アイテム数 | ショップ数 |
|---|---|---|---|
| モブハントの戦利品 | 26533 | 515 | 15 |
| セントリオ記章 | 10307 | 345 | 13 |
| トロフィークリスタル | 36656 | 333 | 10 |
| バイカラージェム | 26807 | 231 | 42 |
| 同盟記章 | 27 | 221 | 7 |
| 蒼天街振興券 | 28063 | 117 | 3 |
| コスモクレジット | 45690 | 86 | 2 |
| 十二都市銀貨 | 45043 | 74 | 4 |
| ボズヤ古銭 | 31351 | 40 | 1 |

Tier 1〜3 と同じ `ExchangeResolver` をそのまま通すため、**個別実装は不要**。UI から通貨を選べるようにするだけで対応できる。
「ユーザーが任意に設定した交換用通貨」（文書A §1）はこの Tier で満たされる。

### Tier 5 — 対応外（明示的にスコープ外とする）

| 対象 | 理由 |
|---|---|
| ギル販売（`GilShop`） | 「交換」ではなく購入。通貨監視のループが成立しない |
| FC クレジット（`FccShop`） | FC 権限依存で自動化リスクが高い |
| 廃棄ショップ（`DisposalShop`） | アイテムを失う操作。誤爆時の被害が大きい |
| くじ交換（`LotteryExchangeShop`） | 結果がランダムで「交換結果検証」が成立しない |
| 無人島（シェルダレースクリップ 37549/37550） | 専用 UI（`CtsMjiSpecialShop`）で系統が別 |
| マンダヴィル・ゴールドソーサーポイント / 対人戦績 | 取得手段が AutoDuty 周回と接続しない |

Tier 5 は「将来やらない」ではなく「MVP〜Phase 4 では対象にしない」という意味。系統 A に落とし込めるものは後から追加できる。

## 3. 実装方式：ExchangeResolver 一本化

系統 A〜D をすべて同一インターフェースへ正規化する。

```csharp
// 通貨 + 交換先アイテム + キャラクター状態 → 実行可能な交換定義
ExchangeDefinition? Resolve(uint currencyItemId, uint rewardItemId, CharacterContext ctx);

public sealed record ExchangeDefinition
{
    public ExchangeChannel Channel { get; init; }   // SpecialShop / GrandCompany / Inclusion
    public uint CurrencyItemId { get; init; }
    public uint RewardItemId { get; init; }
    public int  CurrencyCost { get; init; }         // 1 回あたりの必要通貨
    public int  RewardQuantity { get; init; }       // 1 回あたりの取得数
    public uint ShopId { get; init; }               // SpecialShop.RowId / GCScripShopCategory.RowId
    public int  EntryIndex { get; init; }           // ショップ内のエントリ位置（ID から実行時に逆引き）
    public uint NpcDataId { get; init; }
    public uint TerritoryId { get; init; }
    public Vector3 NpcPosition { get; init; }
    public int? RequiredGrandCompanyRank { get; init; }
    public uint? RequiredQuestId { get; init; }
}
```

NPC 位置の解決経路（`ItemVendorLocation` が実装している経路と同一、実在確認済み）：

```
ENpcBase.ENpcData[]  →  SpecialShop / GCShop / InclusionShop の ID
       ↕ 間接参照
PreHandler / TopicSelect / CustomTalk
       ↓
ENpcResident（名称） + Level（座標・TerritoryId）
```

### UI 位置依存を避けつつ実際に操作する方法

仕様書の「UI の N 番目を押す、を禁止」という要求と、実際の Addon が index 指定コールバックを要求する現実は衝突する。解決策：

1. シート上で `RewardItemId` からエントリの**行位置**を求める（＝ ID → index の逆引き）
2. ショップを開いた後、**その index の実際のコスト・報酬を読み戻して照合**する
3. 一致した場合のみコールバックを送る。不一致ならエラー（`ExchangeItemNotFound`）で安全停止

これにより「画面の N 番目」ではなく「ID で特定した結果としての index」になり、言語設定にも依存しない。

## 4. 既知のリスク：スクリップだけデータ駆動が完結しない

`UseCurrencyType == 16` のショップでは、コストが ItemId ではなく**クライアント内部の特殊通貨インデックス**で記録されている。実測で出現するインデックスは `{1, 2, 4, 6, 7}`（計 484 ショップ）で、対応は：

| index | 実際の通貨 | ItemId |
|---|---|---|
| 1 | アラガントームストーン:詩学 | 28 |
| 2 | クラフタースクリップ:紫貨 | 33913 |
| 4 | ギャザラースクリップ:紫貨 | 33914 |
| 6 | クラフタースクリップ:橙貨 | 41784 |
| 7 | ギャザラースクリップ:橙貨 | 41785 |

**この対応表はシート内に存在しない。** トームストーン（`UseCurrencyType=4`）が `Tomestones` シートで解決できるのとは対照的に、スクリップは参照先シートが無い。
既存プラグイン（ItemVendorLocation 等）も同じ表をソース内に持ち、パッチごとに手で更新している。

### 本プラグインでの扱い

コードに埋め込まず、以下の三段構えにする。

1. **データファイル化** — `Data/special_currency_map.json` に外出しし、コード修正なしで更新できるようにする
2. **実行時自己検証** — ショップを開いた際に実際のコスト通貨を読み戻し、表と食い違えば警告ログ＋自動補正
3. **デバッグ UI で可視化** — 文書B §45 の「解析データ確認 UI」で現在の解決結果を表示し、ユーザーが誤りを発見できるようにする

新しいスクリップ階層が追加された場合、この JSON に 1 行足すだけで対応できる。

## 5. 通貨監視の実装（全 Tier 共通）

| 取得対象 | 取得元 |
|---|---|
| 現在所持数 | `InventoryManager.GetInventoryItemCount(itemId)` |
| 所持上限 | `Item.StackSize`（トームストーン 2,000 / スクリップ 4,000） |
| 軍票上限 | `GrandCompanyRank.MaxSeals`（現在階級の行） |
| 週上限・週取得量 | `Tomestones.WeeklyLimit` + クライアント側の週取得カウンタ |
| 所属 GC / 階級 | `PlayerState`（GC ID と Rank） |

閾値モードは文書B §22 の 3 種に統一する（軍票以外にも適用）：

- `Fixed` — 固定値（例: 1,800）
- `Percentage` — 上限に対する割合（例: 90%）※ **推奨デフォルト**
- `BeforeCap` — 上限からの残り（例: 上限 − 200）

`Percentage` を既定にすることで、軍票の階級変動にもトームストーン上限の変更にも自動追従する。

## 6. フェーズ計画（対応範囲の段階）

| Phase | 対応系統 | 内容 |
|---|---|---|
| **MVP** | B | トームストーン 1 通貨・1 アイテム。AutoDuty 停止 → vnavmesh 移動 → 交換 → 検証 → AutoDuty 再開 |
| **Phase 2** | B + D | 軍票対応、キャラクター別プロファイル（ContentId 主キー）、階級・上限追従、目標個数、複数プリセット |
| **Phase 3** | B + D | 交換 Queue、1 回の AutoDuty 停止で複数交換、エリア／NPC グルーピング |
| **Phase 4** | C + E | スクリップ対応、収集品納品ループ（納品 → 交換 → 納品） |
| **Phase 5** | A | 汎用 SpecialShop 開放（バイカラー、トロフィークリスタル等をユーザーが任意登録）、デバッグ UI |

## 7. 連携プラグイン（実ソースで確認済みの IPC のみ使用）

いずれも 2026-08-25 時点で GitHub から取得した最新ソースで確認済み。推測した IPC 名は 1 つも含まない。

### AutoDuty（`ffxivcode/AutoDuty`）
```
AutoDuty.Run(uint territoryType, int loops, bool bareMode)
AutoDuty.Start(bool startFromZero)
AutoDuty.Stop()
AutoDuty.IsNavigating() / IsLooping() / IsStopped()
AutoDuty.ContentHasPath(uint) / GetConfig(string) / SetConfig(string, object)
```
※ 「Duty 途中か」を直接返す IPC は存在しない。`IsLooping()` + `ConditionFlag.BoundByDuty` + `TerritoryIntendedUse` の組み合わせで判定する。

### vnavmesh（`awgil/ffxiv_navmesh`）
```
vnavmesh.Nav.IsReady / Nav.BuildProgress / Nav.PathfindInProgress
vnavmesh.SimpleMove.PathfindAndMoveTo(Vector3, bool fly)
vnavmesh.SimpleMove.PathfindAndMoveCloseTo(Vector3, bool fly, float range)
vnavmesh.Path.IsRunning / Path.Stop / Path.NumWaypoints / Path.SetTolerance
vnavmesh.Query.Mesh.PointOnFloor / NearestPoint
```

### Lifestream（`NightmareXIV/Lifestream`）— テレポート用
```
Lifestream.Teleport(uint aetheryteId, byte subAetheryteId)
Lifestream.AethernetTeleport(string)
Lifestream.IsBusy()
Lifestream.ExecuteCommand(string)
```

### AutoRetainer（`PunishXIV/AutoRetainer`）— 競合回避のみ
```
AutoRetainer.PluginState.IsBusy()          // = TaskManager.IsBusy || AutoGCHandin.Operation || Lifestream.IsBusy()
AutoRetainer.PluginState.GetMultiModeStatus()
AutoRetainer.PluginState.GetClosestRetainerVentureSecondsRemaining(ulong cid)
AutoRetainer.GetSuppressed() / AutoRetainer.SetSuppressed(bool)
```

**`SetSuppressed(true)` が競合回避の要**。これを立てると AutoRetainer は
MultiMode / スケジューラ / リテイナーセンス の**新規開始を止めるが、実行中のタスクは中断しない**。
つまり「外部プラグインを強制停止しない」（文書A §39）を守ったまま、交換中の割り込みを防げる。交換完了後に `false` へ戻す。
