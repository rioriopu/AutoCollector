# 28. 移動の角を曲線にする（SmoothNav の組み込み）

ブランチ `feature/smooth-move`（土台 `integration/all-v2` の 33b1683）。**ゲームの中ではまだ確かめていない。**

## 何をするか

vnavmesh の経路は、角で向きを急に変える（直線をつないだ折れ線）。交換所・呼び鈴・FATE へ向かう移動で、角ごとにカクッと向きが変わる。
角を曲線に整えた経路で動かし、人が歩くように角を回らせる。

整える部品は別リポジトリの **SmoothNav**。必要なファイルだけを `AutoCollector/SmoothNav/` へ写して一緒に組み立てる
（相手の PC に原本が無くても組み立てられるように）。**写しは直接直さない。** 原本で直して `tools/sync_smoothnav.py` で写し直す
（原本のコミットと各ファイルの SHA256 を `AutoCollector/SmoothNav/README.md` に控える）。

## 守ること（今までより悪くしない）

- 新しく作る曲線の線は、使う前に確かめる。地上は vnavmesh の点の照会（歩ける面から外れないか）、飛行はゲームの当たり判定（地形・物に当たらないか）。
  ゲームの当たり判定は画面のスレッドでしか呼べないので、待ち行列に積み、毎フレーム 1 ミリ秒まで処理する（`SmoothMoveService`）。
- 公式の経路と同じ線（公式の区間の上の線）は、公式 vnavmesh が通れるとした線なのでそのまま使う。
- 整えられない・間に合わない（0.25 秒）ときは公式の経路で動く。間に合わなかった分は、整い次第、今の位置の近くから乗り換える。
- 経路が無い・頼めないときは、今までどおり vnavmesh 任せ（`SimpleMove.PathfindAndMoveCloseTo`）で頼む。

## どこで使うか

| 場所 | 中身 |
|---|---|
| `Automation/NavigationService.cs` | 有効なら SimpleMove で頼まず、自分で経路を探して（`Nav.PathfindCancelable`）整え、その経路を辿らせる（`Path.MoveTo`）。range の手前で経路を切るので、止まる場所は SimpleMove と同じ（vnavmesh の FollowPath の DestinationTolerance と同じ見方＝最後の点から range 以内）。探索・整える間は「移動中」。到着・止まった・届かないの見張り、止まったときの引き直し（vnavmesh 任せ）は今までと同じ。頼み直し（Reissue）は今の経路を止めない（整った経路で差し替える） |
| `Automation/FateApproach.cs` | 今の確かめ（`Validate`・降下の形 `IsDescentAcceptable`）を通った経路を整え、整えた経路にも同じ確かめをかけて、通ったときだけ使う。途中からの乗り換えはしない（降下の段・経路の見守りとぶつかるため）。段階が変わったら整えた結果は捨てる |
| `Automation/FateRunner.cs` の迂回（`CheckBlocked`） | **公式のまま。** 詰まった所のそばで新しい線を作らない |

## 設定

「設定」タブの「NPC への接近距離」の下：

- 「移動の角を曲線にしてなめらかに動く」（`Config.SmoothMovement`・既定で有効）
- 「飛んで向かうときも曲線にする」（`Config.SmoothFlight`・既定で有効）

## 記録

移動ごとに `[Navigation] 移動の経路：曲線に整えた経路（理由・変えた区間・点の数・秒）` を残す（診断の一覧・dalamud.log・詳細ログ）。
FATE の接近は FATE の記録に「経路を曲線に整えた」「整えた経路を使わない（理由）」を残す。

## 試験

- `python -X utf8 tools/regression/navigation_smooth.py`（22 件）：本物の NavigationService と SmoothNav の写しを、偽物の vnavmesh・ゲームの上で試す。
  曲線の経路で辿らせる・range の手前で切る・探索と整える間は何回見張っても移動中・経路が無ければ vnavmesh 任せ（断られたら受け取られるまで頼み直す）・
  切ってあれば今までどおり・止めたら探索を取り消す・乗り換えは辿っている間だけ・頼み直しは今の経路を止めない。
- `python -X utf8 tools/regression/approach_smooth.py`（9 件）：FateApproach の「整えた経路を使うか決める」所（本物を抜き出す）。
  確かめを通れば使う・整えていなければ公式・読めない座標や終点のずれ・降下で垂直落下になる整えた経路は使わない。
- 判定を 1 か所ずつ壊して、上の試験が見つけることを確かめた（NavigationService 7/7・FateApproach 4/4）。
- 既存の `tools/regression/run.py` は、土台（33b1683）の時点で組み立てに失敗している（`ECommons`・`SharesPlayerBattalion` が見つからない）。今回は触っていない。

## まだ確かめていないこと

- ゲームの中で、交換所・呼び鈴・FATE へ曲線で向かうか、壁や柵に擦らないか、止まる場所が今までと同じか。
- 飛行で、整える処理が 0.25 秒に間に合う割合（間に合わなければ公式の経路で動き出し、整い次第乗り換える）。
