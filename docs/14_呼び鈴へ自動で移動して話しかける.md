# 呼び鈴を探して、歩いて、話しかける

リテイナーの呼び鈴（Summoning Bell）を自動で見つけ、話しかけられる位置まで歩き、
実際に開くまでの一連の処理。**別プラグインへの転用を前提**に、仕組みと落とし穴を中心に書く。

取り出しそのもの（リテイナーを開いてアイテムを引き出す）は範囲外。
呼び鈴が開いて `RetainerList` が出るところまでを扱う。

---

## 0. 全体の流れ

```
[常時] エリアを移る
   └→ 3 分間、2 秒おきに呼び鈴を探す ──→ 見つけたら座標を覚えて保存
                                            （bell-locations.json）

[実行時] 呼び鈴を使いたい
   ├→ 読み込まれている呼び鈴がある？ ──→ その座標へ
   ├→ 無いが、このエリアで覚えている？ ─→ 覚えた座標へ（近づけば読み込まれる）
   └→ どちらも無い ──────────────→ 失敗（歩き回って探しはしない）
           ↓
      vnavmesh で 2.5m 以内まで歩く
           ↓
      距離を実測して 3.5m 以内か確かめる
           ↓
      TargetSystem->InteractWithObject
           ↓
      ConditionFlag.OccupiedSummoningBell が立つのを待つ
           ↓
      RetainerList が開く
```

**要になっている考え方は 2 つ。**

1. **見えている ≠ 話しかけられる。** 検出範囲と対話範囲は別物として扱う
2. **読み込まれていない ≠ 存在しない。** 座標を覚えておけば、見えなくても向かえる

## 1. 呼び鈴を探す

`AutoCollector/Automation/RetainerRestockRunner.cs` の `ScanForBell`。

```csharp
public static IGameObject? ScanForBell()
{
    if (!Player.Available) return null;

    // 名前はシートから引く。番号は言語に依らない
    var bellName = Svc.Data.GetExcelSheet<EObjName>()?
        .GetRowOrDefault(2000401)?.Singular.ExtractText() ?? string.Empty;

    IGameObject? nearest = null;
    var nearestDistance = float.MaxValue;

    foreach (var obj in Svc.Objects)
    {
        if (obj.ObjectKind is not (ObjectKind.EventObj or ObjectKind.HousingEventObject))
            continue;

        var name = obj.Name.ToString();

        var matches =
            (!string.IsNullOrEmpty(bellName) && name.Contains(bellName, StringComparison.Ordinal)) ||
            name.Contains("呼び鈴", StringComparison.Ordinal) ||
            name.Contains("Summoning Bell", StringComparison.OrdinalIgnoreCase);

        if (!matches || !obj.IsTargetable) continue;

        var distance = Vector3.Distance(obj.Position, Player.Position);
        if (distance < nearestDistance)
        {
            nearest = obj;
            nearestDistance = distance;
        }
    }

    return nearest;
}
```

### 押さえどころ

| 項目 | 内容 |
|---|---|
| シート | `EObjName` の **RowId 2000401** が「呼び鈴」 |
| 種別 | `EventObj` と **`HousingEventObject` の両方**を見る |
| 一致 | **含むかどうか**で見る。完全一致にしない |
| 可否 | `IsTargetable` を必ず確認する |
| 距離 | **切らない。** 読み込まれていれば全部拾う |

**`HousingEventObject` を落とさない。** フリーカンパニーの地下工房や個人宅の呼び鈴は
こちらの種別で出る。`EventObj` だけ見ていると、家の中で永久に見つからない。

**名前は含むかどうかで見る。** 実際の名前には接頭辞や装飾が付くことがあり、
言語によっても変わる。シートの値を最優先にしつつ、日本語・英語の直値も予備に置く。
CLAUDE.md の「実在を確認していない名前を創作しない」に従い、直値は実測で確認したものだけ。

**距離で切らない。** 実際の上限はこちらが決める数ではなく、ゲームが読み込んでいる範囲。
`Svc.Objects` に載っていれば座標は正しいので、足りないぶんは歩けばよい。

> 以前は探す範囲を 10m に取り、**そこから動かずに話しかけていた。**
> 実際に話しかけられるのはもっと近い距離のため、
> 「距離が離れています」が出続けるだけで永久に進まなかった。

### 見つからなかったときに何が近くにあるか残す

失敗の原因が追えないと直せない。

```csharp
private static string DescribeNearby()
{
    var near = Svc.Objects
        .Where(x => x.ObjectKind is ObjectKind.EventObj or ObjectKind.HousingEventObject)
        .Select(x => (Name: x.Name.ToString(), Distance: Vector3.Distance(x.Position, Player.Position)))
        .Where(x => x.Distance <= 15f)
        .OrderBy(x => x.Distance)
        .Take(4)
        .Select(x => $"{x.Name} {x.Distance:F1}")
        .ToList();

    return near.Count == 0 ? "近くに触れるものがありません" : $"近くにあるもの: {string.Join(" / ", near)}";
}
```

「近くに呼び鈴がありません（近くにあるもの: 掲示板 4.2 / マーケットボード 8.1）」まで出ると、
**種別の漏れなのか、本当に無いのかがログだけで切り分けられる。**

## 2. エリアを移ったら探し続ける

`AutoCollector/Plugin.cs` の `LearnBellLocation`。毎フレーム呼ぶ。

```csharp
/// <summary>エリアを移ってから呼び鈴を探し続ける時間。</summary>
private static readonly TimeSpan BellScanWindow = TimeSpan.FromMinutes(3);

private void LearnBellLocation()
{
    var territory = Svc.ClientState.TerritoryType;

    // エリアが変わったら、そのエリアぶんの探索をやり直す
    if (territory != this.bellScanTerritory)
    {
        this.bellScanTerritory = territory;
        this.bellScanUntilUtc = DateTime.UtcNow.Add(BellScanWindow);
    }

    this.BellLocations.SaveIfDirty();

    // 移ってからしばらくのあいだだけ探す。ずっと探し続けはしない
    if (DateTime.UtcNow > this.bellScanUntilUtc) return;

    if (!EzThrottler.Throttle("AutoCollector.ScanBell", 2000)) return;

    try
    {
        var bell = RetainerRestockRunner.ScanForBell();
        if (bell is not null)
            this.BellLocations.Remember(territory, bell.Position, bell.Name.ToString());
    }
    catch (Exception ex)
    {
        this.AnomalyLog.Warn("Bell", $"呼び鈴を探せませんでした: {ex.Message}");
    }
}
```

### なぜ「着いた瞬間に 1 回」では足りないのか

**呼び鈴は `Svc.Objects` に載っているものしか見えない。**
エーテライトに着いた地点から呼び鈴が遠ければ、その時点ではまだ読み込まれていない。
1 回だけ探しても見つからない。

そこで **3 分の窓**を開けて、**2 秒おきに**探し続ける。
移動しているうちに読み込まれた時点で覚える。ずっと探し続けはしない。

### なぜエリアの種類で絞らないのか

街・宿屋・地下工房を判別して対象を絞る、という作りにはしていない。

- 呼び鈴が無いエリアでは見つからないだけで、**害が無い**
- 探す手間は `Svc.Objects` を 1 周するだけ
- 絞ると、新しく呼び鈴が置かれた場所に追随できない

判別をやめたぶん、コードから条件分岐がまるごと消えた。

### 覚えていても探し直す

```csharp
// **覚えていても探し直す。**
// 覚えたら二度と見ない作りにしていたため、呼び鈴が動いても古い場所を
// 使い続け、直す手段が「忘れる」ボタンしかなかった。
// エリアへ入るたびに確かめれば、そのボタン自体が要らなくなる。
```

これは設計上わりと大きい。**「覚えたら見ない」にすると、必ず手動の「忘れる」操作が要る。**
毎回確かめる作りにすれば、利用者に操作をさせずに自動で追随する。
場所が変わっていなければ `Remember` が何もしないので、保存は走らない（次節）。

## 3. 場所を覚える

`AutoCollector/Game/BellLocationStore.cs`。`bell-locations.json` に
`エリア番号 → 座標` で保存する。

```csharp
public void Remember(uint territoryId, Vector3 position, string name)
{
    if (territoryId == 0) return;

    var store = this.Load();

    // 動いていなければ書き換えない
    if (store.TryGetValue(territoryId, out var existing) &&
        Vector3.Distance(existing.Position, position) < 1f)
    {
        return;
    }

    store[territoryId] = new BellLocation
    {
        X = position.X, Y = position.Y, Z = position.Z,
        Name = name, SeenAt = DateTime.Now,
    };

    this.dirty = true;
}
```

### 押さえどころ

**1m 動いていなければ書き換えない。** 同じエリアで何度も見かけるので、
毎回書き換えると保存が走り続け、何もしていないのにファイルを触ることになる。

**保存は間隔を空ける。** `dirty` を立てるだけにして、実際の書き込みは 5 秒に 1 回。
終了時に `Dispose` で書き残しを出す。

```csharp
public void SaveIfDirty()
{
    var now = DateTime.UtcNow;
    if (!this.dirty || now < this.nextSaveUtc) return;

    this.dirty = false;
    this.nextSaveUtc = now.AddSeconds(5);
    // ... File.WriteAllText
}

public void Dispose()
{
    this.nextSaveUtc = DateTime.MinValue;   // 間隔を無視して必ず書く
    this.SaveIfDirty();
}
```

**キャラクターでは分けない。** 呼び鈴はワールドの設置物で、誰から見ても同じ場所にある。
キャラクターごとに持つと、同じ場所を何度も覚え直すことになる。

**保存先は `Svc.PluginInterface.ConfigDirectory`。** 設定本体とは別ファイルにしてある。
設定より更新頻度が高く、壊れても再スキャンで作り直せるため、
設定ファイルを巻き込まないようにしている。

**当てが外れたら忘れる**（詳細は 4 節）。
動かせる呼び鈴（ハウジングの調度品）を覚えてしまっても、1 度無駄に歩くだけで済む。

## 4. 歩く

### 行けるかどうかの判定

```csharp
/// <summary>
/// 話しかけられる呼び鈴へ行けるか。
///
/// **「いま話しかけられるか」ではない。** 歩いて行けるかどうか。
/// 読み込まれているものが無くても、このエリアで前に使えた場所を覚えていれば行ける。
/// </summary>
public bool IsBellReachable() => this.FindBell() is not null || this.RememberedBell() is not null;
```

**判定用と表示用を分ける。**

```csharp
/// **判定はここを使う。DescribeBell の戻り文字列で分岐しないこと。**
/// 画面へ出す文言を直した瞬間に動作が変わる。実機でしか現れない壊れ方になる。
```

これは実際に書いてしまっていた。目標の周回を実装した時点では、こうなっていた。

```csharp
var bell = this.restock.DescribeBell();

if (!bell.StartsWith("呼び鈴が見つかりました", StringComparison.Ordinal))   // ← 表示用の文字列で分岐
{
    this.Note($"素材が {shortfalls.Count} 種類足りませんが、{bell}");
    return this.BeginCraftWithinMaterials(preset, goal, out reason);
}
```

**文言を直した瞬間に動作が変わる。** しかもコンパイルは通り、テストでも気づけない。
通しレビューで見つかったので実害は出ていないが、放置すれば実機でしか現れない壊れ方をする。
真偽値を返すメソッドを別に用意して、UI とロジックを切り離す。

### 距離の数え方

```csharp
/// <summary>話しかけられる距離。これより遠いと「距離が離れています」になる。</summary>
private const float BellInteractRange = 3.5f;
```

- **移動の目標** … `BellInteractRange - 1f` = **2.5m**（余裕を取る）
- **話しかける判定** … `BellInteractRange` = **3.5m**（実測値）
- **覚えた場所に着いた判定** … `BellInteractRange + 1f` = **4.5m**

移動の目標を対話範囲より内側に取るのが要点。ちょうどの距離を狙うと、
到着判定の揺れで届かないことがある。

### 移動本体

```csharp
private void TickMoveToBell()
{
    var bell = FindBell();

    // まだ読み込まれていないだけかもしれない。覚えている場所があればそこへ歩く
    if (bell is null)
    {
        if (RememberedBell() is not { } remembered)
        {
            this.StopMoving();
            this.Finish(RestockStep.Error, $"近くに呼び鈴がありません（{DescribeNearby()}）");
            return;
        }

        // 着いても見つからなければ、その記録は当てにならない。忘れる
        if (this.bellMoveIssued &&
            Vector3.Distance(remembered, Player.Position) <= BellInteractRange + 1f)
        {
            this.StopMoving();
            this.bellLocations.Forget(Svc.ClientState.TerritoryType);
            this.Finish(RestockStep.Error, "覚えていた場所に呼び鈴がありませんでした");
            return;
        }

        this.MoveTowards(remembered, "覚えている呼び鈴の場所へ向かっています");
        return;
    }

    var distance = Vector3.Distance(bell.Position, Player.Position);

    // もう届く。歩かない
    if (distance <= BellInteractRange)
    {
        this.StopMoving();
        this.Move(RestockStep.InteractBell, "呼び鈴に話しかけています", 30);
        return;
    }

    if (!this.navigation.IsAvailable)
    {
        this.Finish(RestockStep.Error,
            $"呼び鈴まで {distance:F1} ありますが、vnavmesh が使えないため近寄れません");
        return;
    }

    // 経路は 1 度だけ頼む。毎フレーム頼み直すと積み上がって動かなくなる
    if (!this.bellMoveIssued)
    {
        if (!this.navigation.BeginMove(bell.Position, BellInteractRange - 1f, out var failure))
        {
            this.Finish(RestockStep.Error, $"呼び鈴へ向かえません（{failure}）");
            return;
        }

        this.bellMoveIssued = true;
        this.Note($"呼び鈴へ向かいます（あと {distance:F1}）");
        return;
    }

    var status = this.navigation.Tick(bell.Position, BellInteractRange - 1f);

    switch (status)
    {
        case MoveStatus.Moving:
            this.StatusDetail = $"呼び鈴へ向かっています（あと {distance:F1}）";
            return;

        case MoveStatus.Arrived:
        case MoveStatus.ShortOfTarget:
            // 届く距離まで来たかどうかは、着いたという報告ではなく距離で確かめる
            this.StopMoving();
            this.Move(RestockStep.InteractBell, "呼び鈴に話しかけています", 30);
            return;

        default:
            this.StopMoving();
            this.Finish(RestockStep.Error, $"呼び鈴まで行けませんでした（あと {distance:F1}）");
            return;
    }
}
```

### 押さえどころ

**毎フレーム「探す → 判断する」をやり直す。**
最初に見つけた呼び鈴を握り続けない。歩いているうちに、より近い呼び鈴が読み込まれることがある。
また、覚えた場所へ向かっている途中で本物が読み込まれたら、その時点で本物へ切り替わる。

**経路は 1 度だけ頼む。** `bellMoveIssued` という印を持つ。
毎フレーム `BeginMove` を呼ぶと依頼が積み上がり、**その場から動かなくなる。**

**`ShortOfTarget` を失敗にしない。** vnavmesh が走り終わったのに目的地まで届いていない状態。
呼び鈴がカウンターの内側やメッシュの外にあると起きるが、
**話しかけられる距離には入っていることが多い。**
到着の報告を信じず、次のステップで距離を実測する。

**自分が始めた移動だけを止める。**

```csharp
private void StopMoving()
{
    if (!this.bellMoveIssued) return;   // ← 自分が動かしていなければ触らない
    this.bellMoveIssued = false;

    try { this.navigation.Stop(); }
    catch (Exception ex) { this.anomalyLog.Warn("Restock", $"移動を止められませんでした: {ex.Message}"); }
}
```

無条件に `vnavmesh.Path.Stop` を呼ぶと、**他プラグインが出した移動まで止める。**
印を見てから止める。

### vnavmesh 側の注意（`NavigationService.cs`）

移動の実体はこちらに切り出してある。呼び鈴に限らない話だが、重要なので要点だけ。

| 罠 | 対処 |
|---|---|
| 経路探索に失敗しても例外を握り潰し、経路が空のまま終わる。**「移動失敗」と「移動完了」が IPC 上は同じ** | 距離とタイムアウトを必ず自分で確認する |
| スタック時の自動再試行で走行フラグが false↔true を往復する | **3 回続けて**条件を満たすまで到着と認めない（`RequiredStableFrames`） |
| 走行状態が 3 種類ある | `Path.IsRunning` / `Nav.PathfindInProgress` / `SimpleMove.PathfindInProgress` を**全部**見て、1 つでも進行中なら移動中とみなす |
| エリアが変わると経路が破棄される | `BeginMove` 時の `TerritoryType` を覚え、変わったら `Failed` |
| 配置由来の座標がメッシュに乗っていない | `Query.Mesh.NearestPoint` で床にスナップする |

**目的地を変えるときは先に止めない。**

```csharp
/// vnavmesh の MoveTo は経路探索を積むだけで、今の経路は消さない。
/// 差し替わるのは探索が終わってからで、それまでは元の経路を歩き続ける。
/// ここで止めると、探索が終わるまで棒立ちになる。
```

## 5. 話しかける

```csharp
private void TickInteractBell()
{
    // 開いたことは Condition で確かめる。撃った回数では数えない
    if (Svc.Condition[ConditionFlag.OccupiedSummoningBell])
    {
        this.Move(RestockStep.WaitRetainerList, "リテイナーの一覧を待っています", 30);
        return;
    }

    if (this.Expired())
    {
        this.Finish(RestockStep.Error, "呼び鈴に話しかけられませんでした");
        return;
    }

    // 撃つ間隔を空ける。毎フレーム撃つと何も起きない
    if (!EzThrottler.Throttle("AutoCollector.Bell", 2000)) return;

    var bell = FindBell();

    if (bell is null)
    {
        this.Finish(RestockStep.Error, "近くに呼び鈴がありません");
        return;
    }

    // 離れたまま撃ち続けない。ゲームに「距離が離れています」を出させるだけで進まない
    var distance = Vector3.Distance(bell.Position, Player.Position);

    if (distance > BellInteractRange)
    {
        this.Note($"呼び鈴から {distance:F1} 離れています。近寄り直します");
        this.Move(RestockStep.MoveToBell, "呼び鈴へ向かっています", 60);
        return;
    }

    this.Note($"呼び鈴に話しかけます（{bell.Name}・距離 {distance:F1}）");
    Svc.Targets.Target = bell;
    TargetSystem.Instance()->InteractWithObject((GameObjectStruct*)bell.Address, false);
}
```

必要な using:

```csharp
using FFXIVClientStructs.FFXIV.Client.Game.Control;   // TargetSystem
using GameObjectStruct = FFXIVClientStructs.FFXIV.Client.Game.Object.GameObject;
```

### 押さえどころ

**成功は `ConditionFlag.OccupiedSummoningBell` で判定する。**
`InteractWithObject` を呼んだことをもって成功としない。CLAUDE.md の
「固定時間待機で次へ進まない。実際の状態変化を確認して遷移する」がそのままここに当たる。

**先に `Svc.Targets.Target` を入れる。** 入れずに `InteractWithObject` だけ呼ぶと
通らないことがある。

**2 秒に 1 回だけ撃つ。** 毎フレーム撃つと処理が詰まって何も起きない。

**距離は撃つ直前にもう一度測る。**
到着したつもりでも、`ShortOfTarget` で止まっていれば届いていない。
遠ければ `MoveToBell` へ**戻す**。失敗にしない。この往復ができることで、
メッシュの都合で少し手前に止まる場所でも最終的に届く。

**各ステップに制限時間を持たせる。**

| 区間 | 制限 |
|---|---|
| 呼び鈴へ向かう | 60 秒 |
| 話しかける | 30 秒 |
| リテイナー一覧を待つ | 30 秒 |
| 全体 | 5 分 |

`Move(step, detail, seconds)` でステップを変えるたびに期限を入れ直し、
`Expired()` で切る。どこで止まったかが記録に残る。

## 6. 他プラグインと取り合わない

呼び鈴は AutoRetainer も使う。**開始前に協調的に抑制する。**

```csharp
// AutoRetainer が同じ呼び鈴を使おうとすると操作を取り合う。先に抑制する
this.autoRetainer.Suppress();
```

実体は `AutoRetainer.SetSuppressed(true)` の IPC 呼び出しで、
**新規開始だけを止める。** 強制停止ではない。

> CLAUDE.md:「外部プラグインを強制停止しない。AutoRetainer は `SetSuppressed` による
> 協調的な抑制のみ。緊急停止時も必ず解除する」

**解除を必ず通す。** 正常終了・失敗・例外・利用者の停止、どの経路でも `Finish` を通り、
そこで `Release()` する。抑制したまま落ちると、AutoRetainer が二度と動かなくなる。

## 7. 落とし穴まとめ

| # | 落とし穴 | 対処 |
|---|---|---|
| 1 | 検出範囲＝対話範囲だと思った | 検出は無制限、対話は 3.5m。足りないぶんは歩く |
| 2 | `EventObj` だけ見ていた | `HousingEventObject` も見る。家の中で見つからなくなる |
| 3 | 読み込まれていないものを「無い」と扱った | 座標を覚えて、そこへ歩く。近づけば読み込まれる |
| 4 | エリアに着いた瞬間に 1 回だけ探した | 3 分の窓で 2 秒おきに探し続ける |
| 5 | 覚えたら二度と探さなかった | 毎回探し直す。手動の「忘れる」操作が不要になる |
| 6 | 覚えた場所が間違っていても残り続けた | 着いて無ければ忘れる |
| 7 | 毎フレーム `BeginMove` を呼んだ | 印を持って 1 度だけ。積み上がると動かなくなる |
| 8 | 無条件に `Path.Stop` を呼んだ | 自分が始めた移動だけ止める |
| 9 | `ShortOfTarget` を失敗にした | 距離を実測して判断する。多くは届いている |
| 10 | 表示用の文字列で分岐した | 真偽値を返すメソッドを別に用意する |
| 11 | 話しかけた回数で成功を数えた | `OccupiedSummoningBell` が立つのを待つ |
| 12 | 毎フレーム `InteractWithObject` を撃った | 2 秒に 1 回 |
| 13 | 遠いまま撃ち続けた | 距離を測り直して移動へ戻す |
| 14 | AutoRetainer と取り合った | `SetSuppressed(true)`。**解除を全経路で通す** |

## 8. 最小構成へ落とすなら

呼び鈴に限らず「特定のオブジェクトへ歩いて話しかける」の骨格はこれだけ。

```
定数
    InteractRange      対話できる距離（実測で決める）
    MoveRange          InteractRange - 1（移動の目標）

状態
    moveIssued         自分が移動を出したか

毎フレーム（MoveTo ステップ）
    1. 対象を探す（無制限・最近傍・IsTargetable）
    2. 見つからない → 覚えている座標へ。着いて無ければ忘れて失敗
    3. 見つかった   → 距離 <= InteractRange なら次のステップへ
    4. moveIssued が false → BeginMove して印を立てる
    5. moveIssued が true  → Tick の結果で分岐
                             Arrived / ShortOfTarget → 次のステップへ
                             Moving                  → 続ける
                             それ以外                → 失敗

毎フレーム（Interact ステップ）
    1. 成功条件（ConditionFlag / Addon）が満たされたら次へ
    2. 期限切れなら失敗
    3. スロットル（2 秒）
    4. 距離を測り直す。遠ければ MoveTo へ戻す
    5. Target を入れて InteractWithObject
```

**ステップごとに期限を持たせ、成功は必ず「状態の変化」で確かめる。**
この 2 つを守れば、対象が呼び鈴でも NPC でも採集ポイントでも同じ形で書ける。
