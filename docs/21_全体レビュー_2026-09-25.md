# オートコレクター 全体レビュー（2026-09-25）

「プリセットの監視する通貨、数理しか選べない」という報告を起点に、
通貨まわりと、FATE 周回で加えた変更の影響範囲を調べた。

---

## 1. 監視する通貨が 1 件しか選べない（修正済み）

### 本来どうなるはずか

ゲームデータ（ver 2026.09.15）を直接読んで実測した。本来はこれだけ並ぶ。

| 区分 | 中身 |
|---|---|
| アラガントームストーン | 哲学 / 詩学 / 数理 / 記憶 / 天文（5件） |
| スクリップ | クラフター紫・橙 / ギャザラー紫・橙（4件） |

### 原因は 3 つあった

いずれも「一覧が痩せても誰も気づかない」作りが共通の原因。

#### ① 特殊通貨の対応表が、控えを丸ごと捨てていた

`SpecialCurrencyMap.Entries` は

```csharp
runtimeMap.Count > 0 ? runtimeMap : fallbackMap
```

で、**クライアントから 1 件でも取れたら控えは一切見ない**としていた。

`CurrencyManager.SpecialItemBucket` は、そのキャラクターがまだ触れていない
スクリップを載せていないことがある。数件だけ取れた時点で控えが捨てられ、
スクリップが一覧から消える。

→ **重ねて使う**ようにした。同じ番号が両方にあればクライアント側を採る。

#### ② 交換の一覧が空のとき、スクリップを全部落としていた

`CurrencyCatalog.UsableCurrencies()` が 0 件を返すと、
「使える通貨が 1 つも無い」と読んでスクリップが全滅する。

0 件なのは**絞り込みの材料が無いだけ**で、使えないと分かったわけではない。

→ 材料が無いときは**絞らない**ようにした。

#### ③ 選択中の通貨が一覧から消えると、黙って書き換わっていた

画面は一覧から番号で選ばせており、見つからないと `index = 0`（＝先頭の
トームストーン）を指す。その状態で何か操作すると、
**利用者が選んだ覚えのない通貨が保存される。**

実際、保存済みの設定には橙貨（41784）と紫貨（33913）を選んだプリセットが
残っていた。つまり以前は選べていたものが、あとから消えている。

→ 選択中のものは「選択中（一覧に無い）」として**必ず一覧に出す**ようにした。

### この不具合はいつからあったか

**FATE 周回の作業では通貨まわりのコードに一切触れていない。**

`integration/all` との差分で `Game/` 配下にあるのは FATE の新規 3 ファイルのみ
（`FateScanner` / `FateTokenService` / `FateZoneCatalog`）。
`CurrencyCatalog` `TomestoneService` `SpecialCurrencyMap` `PresetTab` は無変更だった。

`UsableCurrencies()` による絞り込みは 2026-09-13 のコミット `6f78ba6`
「納品だけを反復する不具合を直し、通貨の一覧を整える」で入っている。
**0.1.4.2 時点から存在していた不具合。**

## 2. アンロード時に FATE 周回が止まらない（修正済み）

緊急停止は稼ぎ手ごしに FATE を止めていたが、その経路は
利用者が明示的に止めたとき（`stopExternalAutomation = true`）しか通らない。

プラグインのアンロードは `false` で呼ぶため、
**BMR のプリセットと AI が有効なまま残る。**
プラグインを外したのに戦い続け、敵を追い続けることになる。

→ 緊急停止の本体で `FateRunner.Stop` を無条件に呼ぶようにした。
`Stop` は走っていなくても BMR の解除だけは必ず行うため、通してよい。

## 3. FATE 周回の変更が既存機能に与える影響

既存ファイルへの変更は**削除 5 行のみ**で、残りはすべて追加。

| ファイル | 変更 | 影響 |
|---|---|---|
| `NavigationService.cs` | +16/-2 | オーバーロード追加のみ。既存の 3 引数版は `fly:false` へ転送するため、交換・リテイナーの移動は完全に同じ挙動 |
| `IpcGate.cs` | +10 | 4 引数オーバーロードの追加のみ |
| `SafetyGuard.cs` | +78 | `IsSafeToRunFate` の追加のみ。既存の判定には触れていない |
| `Config.cs` | +94 | FATE 設定の追加のみ |
| `MainWindow.cs` | +5 | タブ追加のみ |
| `Plugin.cs` | +53 | サービス登録・Tick・停止処理 |

### 移動の実体を分けてある

`FateRunner` には**専用の `NavigationService`** を渡している。

```csharp
new NavigationService(this.AnomalyLog, this.Vnavmesh)
```

交換の移動と同じ実体を使うと、片方を止めたときにもう片方の経路まで消える。

## 4. 同じ書き癖が他に 4 箇所あった（修正済み）

通貨の件と同じ「一覧が空になったのを、そういうものだと受け取ってしまう」形。

| 場所 | 症状 |
|---|---|
| `CollectableRewardService.Build()` | 収集品の報酬が 1 件も分からないまま固定 |
| `CraftPlanService.Build()` | 作れる収集品が 0 件のまま固定 |
| `CraftPlanService.ListJobs()` | ジョブの一覧が空のまま固定 |
| `CollectablesNpcService.List()` | 納品窓口が見つからないまま固定 |

どれも早期 return と `catch` の両方で `return this.cache = result;` としており、
**シートがまだ引けない時機に一度呼ばれると、空のまま固定される。**
やり直す口が無いため、プラグインを入れ直すまで直らない。

これらは連鎖する。

```
報酬の索引が空 → 作れる収集品が 0 件
  → 製作計画タブが「作れる収集品が見つかりません」のまま動かない
```

`CollectableSourceService.cs:102-107` に**既に正しい形が書かれていた**
（空なら控えない・例外時は代入せずに返す）ので、それを 3 つへ広げた。

### 製作計画タブの選択も直した

```csharp
Math.Max(0, FindIndex(...))
```

選択中のものが一覧から消えると先頭へ丸める。
画面には先頭が出るが、実際に使われるのは変数に残った古い値のままで、
**両者が食い違う。** 消えていたら選び直しにした。

## 直していない既知の問題

### プリセットの系統・種別が、位置だけで選ばれている

`Ui/PresetTab.cs:691-694`, `:739-742`

`categoryIndex` / `seriesIndex` は**位置**だけを持ち、
中身の同一性（カテゴリ名や `SpecialShopId`）を持たない。
範囲外になったら 0 に戻すだけで、**範囲内のまま中身が入れ替わった場合は
何の警告もなく別の系統・種別の品が並ぶ。**

`InclusionShopCatalog.ListCategories()` は特殊通貨の対応表が
クライアント由来に入れ替わったときに一覧を作り直すため、
設定画面を開いたままこれが起きると起こりうる。

**直すには位置ではなく名前・`SpecialShopId` で選び直す作りに変える必要があり、
交換の流れ全体に触ることになる。いまは動いているため、手を付けていない。**
