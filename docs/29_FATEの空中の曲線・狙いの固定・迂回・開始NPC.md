# 29. FATE：空中の曲線・狙いの固定・届かないときの迂回・開始 NPC の順送り

ブランチ `feature/smooth-move`（28 の続き）。**ゲームの中ではまだ確かめていない。** 回帰試験・壊して確かめるは下の「確かめたこと」。

利用者の要望（2026-10-10、28 の版を試したあと）：

1. 地上の曲線の動きを空中にも。
2. FATE の戦闘で、1 回狙ったら倒れるまで狙いを変えない（他の戦闘の仕組みと取り合いになりやすい所なので注意）。
3. 狙った敵との間に岩などがあり、4 秒攻撃を始められない（近接職は近接攻撃ができない）なら、敵を目標にメッシュで迂回経路を引いて近づく。
4. NPC に話しかけて始まる FATE は、周りの NPC に近づいて話しかける。3 秒で始まらなければ別の NPC へ（A → 3 秒変化なし → B で開始 → C には話しかけない）。

## 1. 空中の曲線（`Automation/FateApproach.cs`・`Automation/FlightJoin.cs`）

**原因（10-10 12:39〜12:55 の記録）**：飛行の進入は「真上へ離陸 → 止まって外周上空への経路を求める → 外周上空で止まって降下の経路を求める」。
段の境目ごとに止まって向きを変えていた（離陸の後 0.1〜0.55 秒、外周で 0.1〜0.18 秒）。さらに外周上空への長い経路（7〜8 点）10 本のうち 4 本が、
整える予算 0.25 秒に間に合わず公式のままだった。

**直し方**：乗る・離陸する間（実機で 2 秒ほど）に、外周上空への経路と降下の経路を**先に**求め、1 本につないで曲線に整えておく（予算 1.5 秒）。

- 経路は離陸の合図の点（真上 5m）から求める。離陸を確かめたら止めずにそのまま渡す。合図の点がすぐそばなら飛ばして 2 点目へ斜めに上がる（`FlightJoin.FromHere`）。
- つないだ経路では外周点の角も曲線の対象になる。外周点に着く代わりに「外周を越えた」（着地点までの水平距離が外周点より短い）で降下の段へ移る。止めない（`FlightJoin.PassedEntry`）。
- 確かめは今までと同じものを、経路を求めた出発点で測る（`Validate`・`IsDescentAcceptable` に出発点を渡す形を足した）。
  降下の経路が確かめを通らないとき（垂直落下になる等）は外周上空までだけを使い、降下は今までどおり外周で求め直す（段に分けて降りる）。
- 先に求められない・15 秒たっても求まらない・曲線にする移動を切ってあるときは、今までどおり段階ごとに求める。
- vnavmesh は経路探索を 1 本ずつ順に処理する（`NavmeshManager.QueryPath` の `ExecuteWhenIdle`）ので、続けて 2 本頼んでよい。

## 2. 狙いを倒れるまで固定（`Game/TargetLock.cs`・`Game/FateTargetService.cs`・`Ipc/RotationSolverControl.cs`）

**原因**：

- RSR を `/rotation Auto` で入れていた。Auto は次に撃つ技の相手へハードターゲットを書き換える（RSR `RSCommands_Actions.cs:310-316`。`!DataCenter.IsManual` のとき）。
- AutoCollector は「いまのハードターゲットが狙ってよい敵なら、それを使う」だったので、RSR が替えた狙いをそのまま受け入れた。
- 10-10 12:40:09〜18 の 9 秒で 6 回、パックジャッカルと 40m 先のジャッカルの間を行き来していた。

**直し方**：

- 自分が固定した相手を正とする。他から替えられていたら戻す（`LockAction.Restore`。戦闘の資料 8 章の取り合いと同じ考え方）。戻した回数を記録に残す。
- 固定を外すのは、倒れた・消えた・狙ってよい敵でなくなった・フォーローンが出た（docs/27 §4-3 の要件）・味方の NPC を狙っていて本物の敵がいる、のときだけ。
  ObjectTable の枠の使い回しは名前の番号（NameId）で見分ける。
- 次の相手は「味方でない → いま攻撃してきている → 大きい → 近い」。攻撃してきた敵を先に片付ける（反撃の方針・戦闘の資料 7 章）。
- 固定が無いときに、狙ってはいけない敵（FATE 外で敵視も無い）が他から置かれていて、ほかに狙う相手も居なければ外す（Henched はハードターゲットを殴るため）。
- RSR は **Henched** で入れる（`/rotation Henched`。導入中の 7.5.6.21 の DLL に有ることを確かめた）。
  Henched は `IsManual` が立ち、置いたハードターゲットにだけ単体技を撃つ。戦闘後の自動 OFF（AutoOffAfterCombat）も受けない。
  範囲攻撃は周りを巻き込むが、FATE では敵をまとめて倒せるので触らない。
- BMR は今までどおり AutoTarget の Retarget=Never（一時方針）で、狙いを書き換えない。
- RSR の TargetFreely（狙いが空なら近くの敵を狙う）は、この PC の設定では切（10-10 に `RotationSolver.json` で確認）。設定は書き換えていない。

## 3. 届かないときの迂回（`Game/AttackReach.cs`・`Automation/AttackWatch.cs`・`FateRunner.TickReachTarget / TickDetour`）

- 攻撃が届くかはゲームに聞く：ジョブの代表の技（近接の役割＝いちばん低いレベルの技＝近接の射程。遠隔＝いちばん遠くまで届く技）で
  `ActionManager.GetActionInRangeOrLoS`（0・565＝届く）。さらに RSR と同じ視線のレイ（足もと+2m 同士・`RaycastMaterialFilter`）で遮られていれば届かないとする
  （RSR はそれで攻撃の候補から外す）。AutoMobFarm の AttackReach・GameWorld.RsrSightBlocked と同じ。
- 狙った敵へ届けば自分の移動はやめて BMR・RSR に任せる。届かないうちは、近接は近接の間合いまで、遠隔は 15m までメッシュの経路で詰める（今までどおり）。
  戦闘の前でも狙った敵がいればこの形で動く（以前は「近い敵の 15m まで」→ BMR）。
- 4 秒届かないままなら迂回：まず敵の位置（メッシュの行ける点へ寄せる）へ経路を引く。手前で切れる・着いても届かない・3 秒進まない（岩に向かって走り続ける）なら、
  敵の周り 8 方向の点を自分に近い側から順に試す（近接は敵の縁から 2m、遠隔は 6m）。使い切ったら最初へ戻る（諦めない）。届いた瞬間にやめる。
- ついでに直した：戦闘に入った直後、15m で引いた経路を 3.5m で見張り、経路の終点で「目的地まで 15.1 ヤルム残っています」を毎フレーム記録していた（10-10 の記録で 45 件）。
  見張りは引いたときと同じ距離で見る。記録も 1 回の移動につき 1 回だけ（`NavigationService`）。

## 4. 開始 NPC の順送り（`Automation/StartAttempts.cs`・`Automation/FateStarter.cs`）

- 対象は「準備中（Preparing）で開始役の番号がある」FATE（AutoFATEGrind の `AwaitsNpcStart` と同じ見分け方）。
- 候補：ゲームが指定した開始役（`FateContext.MotivationNpc`）と、FATE の周り（円の半径か 20m の大きいほう＋20m）の EventNpc。
- 開始役を最初に試す（実機では 10-10 12:48・12:50 の 2 件ともこれで始まった）。開始役がまだ見えなければ 5 秒まで待つ。そのあとは近い順。
- 話し終えて（会話の窓が閉じて）3 秒たっても始まらなければ次の NPC へ。窓が出なければ話しかけてから 3 秒。始まれば以後は話しかけない。
- **指定外の NPC の「はい／いいえ」・選択肢は、文に FATE の名前か「F.A.T.E」が入っているときだけ押す。** それ以外は閉じる（運び屋の移動・店を開かない）。
  開始の確認文は Addon 表には無かった（「F.A.T.E」を含む行を全部調べて、ボタン名「JOIN F.A.T.E.」だけ）。FATE ごとの会話の側にあると見られるため文で見分ける。
  ゲームが指定した開始役は今までどおり「はい」・選択肢の先頭。
- 近づけない NPC（30 秒）はその NPC だけ諦めて次へ。全員に話しかけても始まらなければ、今までどおり 60 秒で一時的に見送る（次の NPC を試し始めるたびに数え直す）。
