## レビュー

5 つの観点で検証し、出た指摘を 1 件ずつ反証にかけた。

```
指摘 49 件 → 残った 26 件 / 反証で落ちた 23 件
```

反証を通したのは、**誤った指摘で正しいコードを壊すのを防ぐため。**
落ちた 23 件には「消えている」「実在しない API」という強い主張も含まれており、
そのまま直していたら動くものを壊していた。

### 直したもの（26 件）

#### 交換と FATE がまったく連動していなかった（blocker × 2）

`FateEarner` は完成していたのに、**どこからも呼ばれていなかった。**

```
EarnerRegistry.BeginSuspendAll / TickSuspendAll / AllAtSafeBreak … 呼び出し 0 件
FateEarner.TickSuspend / TickResume / MarkInterrupting          … 呼び出し 0 件
```

これは**こちらの設計が招いた。**
稼ぎ方のモジュール化で `EarnerRegistry` にまとめ口を作ったが、
止める順序（Artisan → AutoRetainer 抑制 → AutoDuty）が載荷条件だったため、
交換からは `combat` / `crafter` を名指しで呼ぶ形に留めた。
`docs/15` に「段 7 でここを畳むときは、AutoRetainer の抑制をどこへ置くかを先に決めること」
と書いて先送りにした。**3 人目の稼ぎ手が、その前に来た。**

名指しで呼ぶ形は、稼ぎ手が増えたときに**黙ってすり抜ける。**

直したこと:
- `ExchangeExecutor` に `FateEarner` を渡し、中断と復帰の段で呼ぶ
- 順序は保つ（FATE を先に止め、復帰も FATE を先に戻す）
- 切れ目の確認は**登録簿ごし**（`AllAtSafeBreak`）にした。
  誰に聞くかを書き並べないので、次に稼ぎ手が増えても素通りしない

これが無いと、交換所へ向かう経路と次の FATE へ向かう経路が
同じ vnavmesh へ交互に積まれ、**どちらにも着かない。**
FATE の最中や納品の報酬待ちでも割り込み、達成度と報酬を捨てていた。

#### 納品 FATE の所持数が常に 0（blocker）

FATE の収集品は**キーアイテム**に入る。鞄には入らない。

```csharp
inventory->GetInventoryItemCount(item)   // 鞄とアーマリーを見る → 必ず 0
```

何個集めても 0 なので、**納品の段取りへ一度も入れなかった。**
`InventoryType.KeyItems` から数えるようにした
（BossMod Reborn も同じ場所を見ている）。

#### テレポ失敗で毎フレーム再送（blocker）

諦めたあと `teleportStartedUtc` に `DateTime.MinValue` を入れていた。
`AdvanceZone` が「移れる別のマップがありません」で戻ると、
**次のフレームも時間切れになり、間引きの無い警告を出しながら撃ち直し続ける。**
記録は 200 件の輪なので、数秒で本来見るべき警告が全部押し出される。

番兵をやめ、諦めたら現在時刻へ測り直す。3 か所に散っていた同じ処理を 1 つにまとめた。

#### AutoRetainer まわり（major × 3）

**抑制の持ち主を持つようにした。**

立てる場所が 3 つある（交換・取り出し・ベンチャー回収）のに、
「自分が立てたか」を **bool 1 本**で持っていた。
そのため**ベンチャー回収が、交換の立てた抑制を横から外せた。**
交換の最中に AutoRetainer が動き出し、同じ呼び鈴で操作を取り合う。
しかも交換が最後に外そうとしても旗が倒れていて空振りする。

立てた本人だけが外せるようにした。終了時だけは持ち主を問わず外す
（立てたまま終わると利用者の AutoRetainer が止まったままになる）。

**`AbortAllTasks` をやめた。**

プロジェクト指示は「外部プラグインを強制停止しない。
AutoRetainer は `SetSuppressed` による協調的な抑制のみ」と定めている。
呼び鈴を閉じる前に強制停止を撃っており、こちらが頼んだ回収だけでなく
AutoRetainer が自分で積んでいた処理（別リテイナー・潜水艦・GC 納品・修理）まで
一緒に落としていた。**切られた側に戻す手段が無い。**

協調的な抑制に替え、終わる経路すべてで戻すようにした（`FinishUp`）。
`TryAbort` の口そのものを消した。残すとまた呼ばれる。

#### 停止後の見張りが他の移動を巻き添えに（major）

FATE を止めた直後の 20 秒間、vnavmesh の経路を**持ち主を見ずに**捨てていた。
交換の移動・呼び鈴への移動・納品窓口への移動・AutoDuty のダンジョン内の移動が
毎フレーム止められ、「歩き出してすぐ止まる」を繰り返していた。

経路の終点が、止めたとき向かっていた場所と合うものだけ捨てる。
**判断がつかないときは捨てない**側に倒した。
